# 習慣の「作る形」（型・2分チェック・摩擦の診断）

日付：2026-10-10
種別：実装
状態：一部完了（ローカルで動作確認済み。本番の確認は末尾の「確認できていないこと」を参照）

## 結論

習慣の作成・編集フォームを「① きっかけ（〜したあとに）→ ② 最小の行動（〜する）→ ③ そのあとの祝い」の
流れにし、最小版が長そうなときの「もっと小さくしませんか」と、「始めるまでの手順」の診断を足した。
すべて任意・1タップで、案内を無視してそのまま保存できる。祝いと手順数は Supabase にも同期する。
「やった」を押した直後の一言に、決めた祝いを添える。

習慣タブの土台（[習慣タブを足す](2026-10-10-習慣タブを足す.md)）の次の段。

## 仕組み

- **D2 の判定**（`minimalSizeCheck`）: 全角・漢数字を直したうえで、3分以上を表す語（`30分`・`1時間`・`半日`・`5min`・`二十分`）、
  または25文字を超える文を「大きい」とする。2分・30秒・短い行動は出さない。「十分に」のような副詞は時間と取らない。
- **案内**: 入力中にその場で出す（保存は欄を離れたとき、という従来の約束は変えない）。
  「（核）（1分だけ）」「（核）前の準備だけ」「最初の1つだけやる」と「このまま」。「このまま」で同じ文字列のあいだは消える。
- **D4**: 手順 0・1・2・3・4+ から選ぶ（もう一度押すと外れる＝未回答）。3以上で減らす案を出す。
- **D1 の祝い**: 「『よし』と言う／ガッツポーズ／好きな飲み物」の選択肢と自由入力。選んだ祝いは
  「やった！ 12日連続 ／ 祝い：「よし」と言う」のように添える。できなかった・休みには添えない。
- **既存データ**: 新しい項目は任意で、無い習慣は `undefined` として読み `null` 扱い。
  形の変更だけなので `SCHEMA_VERSION` / `MIGRATIONS` は上げていない（既存の `where` `cue` と同じ扱い）。
- **同期**: `habits` に `celebration text`・`friction_steps smallint` を追加（NULL可・既定NULL。追加のみ）。
  送る値は `normalizeFrictionSteps` で 0〜4 か null に丸め、壊れた値で全件が拒否されるのを防ぐ。
  受け取りは `habitFromRow`。`sync.ts` は行ごと `habitToRow` / `habitFromRow` を通すため変更不要。

## データベース

適用前の `habits` は 12 列（`celebration` / `friction_steps` なし）、行数 3。読み取りのみで確認してから適用した。

```sql
alter table public.habits add column if not exists celebration text default null;
alter table public.habits add column if not exists friction_steps smallint default null;
comment on column public.habits.celebration is 'やったあとの祝い（任意の一言・しぐさ）';
comment on column public.habits.friction_steps is '始めるまでの手順数 0〜4（4は4以上）。未回答はNULL';
```

適用後: 2列とも `is_nullable = YES`、`column_default = null`。既存3行は両列とも NULL（`count(celebration)=0`）。
プロジェクト `jvtfxrzpqtlqukxtftjn`、マイグレーション名 `habits_celebration_friction_steps`。
リポジトリにはこれまでSQLの置き場が無かったので、Supabase CLI の慣習に合わせて `supabase/migrations/` を作った。

## 残っていること

- 「小さくする案」は定型文のみ（行動の内容を理解した案ではない）。使われ方を見て、案を増やすか決める
- 手順数は記録だけで、見直し画面（R2・V2）にはまだ使っていない
- 「今日」画面の習慣チェックリスト側では、祝いの一言を出していない（習慣タブのみ）
