## 変更内容・調査結果

### 改善1：時間割の「消す」を取り消すと、完了済み習慣の記録が戻らない（修正）

**症状**：時刻を決めた習慣の枠を完了させたあと、時間割（`/plan`）でその枠を
「消す」→ 直後に出る「取り消す」を押すと、**枠は完了済みの見た目で戻るのに、
習慣の連続日数・達成率には反映されない**まま。押した本人には何も表示されず、
気づく手立てがない。

**原因**：`deleteTimeBox()` は、完了済みの習慣枠を消すときにその枠が付けた
「できた」記録（`HabitLog`）も一緒に取り消す（2026-09-11 その2 で実装済み）。
一方、`/plan` の「消す」操作の取り消し（`revert`）は `upsertTimeBox(before)` で
枠だけを書き戻しており、消えた記録の巻き戻しが対になっていなかった。
[src/app/plan/page.tsx](../../src/app/plan/page.tsx) の `remove()` 関数。

`moveByDrag()`（ドラッグでの移動・リサイズの取り消し）は完了状態そのものを
変えないので、この欠落は起きない。`/list` の削除には取り消し機能自体が無いため、
影響するのは `/plan` の「消す」だけだった。

**直し方**：[src/lib/storage.ts](../../src/lib/storage.ts) に
`undoDeleteTimeBox()` を追加した。`upsertTimeBox()` で枠を戻したあと、
`habitId` と `completedAt` が揃っていれば `setHabitLog()` で記録も戻す。
`deleteTimeBox()` が記録を消す条件（習慣に紐づく・完了済み）と対称にしてある。
`/plan` の `remove()` の `revert` をこの関数に差し替えた。

### 改善2：整理の待ち時間、75秒間ずっと同じ文言（修正）

**背景**：[2026-09-14-目標の整理が失敗した原因.md](2026-09-14-%E7%9B%AE%E6%A8%99%E3%81%AE%E6%95%B4%E7%90%86%E3%81%8C%E5%A4%B1%E6%95%97%E3%81%97%E3%81%9F%E5%8E%9F%E5%9B%A0.md)
の調査で、`/api/structure` は実データで**75.3秒**かかることが分かっている。
制限時間の打ち切り（60秒）自体は直したが、`/big`・`/card` の待ち画面は
「あなたの言葉を整理しています…」の3点パルスのまま75秒間変化がなく、
本人が「止まっているのでは」と閉じたくなる作りが残っていた。
閉じると `signal: req.signal` 経由で生成そのものが中断される
（AGENTS.mdの規約どおり）ので、閉じてしまうと対話をもう一度最初から
整理し直すことになる。

**直し方**：経過時間で文言を変える純粋関数
[src/lib/structuring-wait.ts](../../src/lib/structuring-wait.ts) の
`structuringMessage()` を追加し、`/big`・`/card` で重複していた待ち画面を
共通コンポーネント [src/components/StructuringWait.tsx](../../src/components/StructuringWait.tsx)
に切り出した。

| 経過時間 | 文言 |
|---|---|
| 〜12秒 | あなたの言葉を整理しています… |
| 12〜35秒 | 実行できる形に、じっくり落とし込んでいます… |
| 35〜60秒 | もう少しで終わります。閉じずにお待ちください… |
| 60秒〜 | 時間がかかっていますが、続けています。閉じると最初からやり直しになるので、もう少しだけお待ちください… |

AIの呼び方（思考トークンの量）には触れていない。R17（待ち時間そのものを
縮めるか）は「整理の質が落ちる可能性があり、比較に課金が要る」ため判断待ちの
まま残しており、これはその判断を待たずに実施できる、体感だけを改善する変更。

### 改善3（判断待ち）：中間目標が日々の画面から見えない

**いまの状態**：中間目標（週/月、`CheckpointEditor` が持つ機能）を検索したところ、
参照しているのは [src/app/goals/page.tsx](../../src/app/goals/page.tsx) と
[src/app/goal/[id]/page.tsx](../../src/app/goal/%5Bid%5D/page.tsx) だけだった。
`CheckpointEditor` 自身の空状態の文言は
「大きな目標を、今週・今月やることに分解しておくと、**期限が近づいたときに
『今なにをやるべきか』が迷わなくなります**」と謳っているが、
日々の行動画面である `/list`（今日やること）・振り返りの `/me`・`/home` の
どこにも中間目標は一切出てこない。`nearestActive()`（一覧に出す
「いちばん今見るべき1件」を選ぶ関数、[src/lib/checkpoint.ts](../../src/lib/checkpoint.ts)）
は存在するが、呼び出しているのは `/goals` の一覧描画だけだった。

**なぜ直さなかったか**：このアプリの中心的な価値（対話→時間割・習慣・振り返り
で行動に移す）に照らすと、せっかく作った中間目標が「わざわざ目標一覧を
開かないと見えない」のは機能の約束と実態がずれている、と判断した。
ただし、どこに・どう出すか（`/list` の先頭に1行だけ出す／`/me` の週次振り返りに
含める／両方）は画面設計の判断であり、`/list` は最も使用頻度が高い画面のため
迂闊に要素を足すと日々の見た目を崩す。R11（未ログイン利用者への案内をどこに
置くか）と同種の「要素を1つ足す」判断のため、実装はせず残件に記録した。

## 仕組みの説明

```
時間割で完了済みの習慣枠を「消す」
  → deleteTimeBox(): 枠を消し、その枠が付けた habitLog（done）も消す
  → 「取り消す」を押す
       修正前: upsertTimeBox(before)  … 枠だけ戻る。記録は戻らない
       修正後: undoDeleteTimeBox(before)
                 → upsertTimeBox(before)
                 → habitId と completedAt があれば setHabitLog() で記録も戻す
```

```
/big・/card で完了を押す → /api/structure へ送信
  → 経過時間を1秒ごとに測り、structuringMessage(経過ms) で文言を切り替える
  → 75秒前後で整理が返り、下書き選択画面に進む
```
