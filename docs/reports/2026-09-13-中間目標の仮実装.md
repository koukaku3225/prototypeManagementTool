## 変更内容・調査結果

### データモデル

`src/types/goal.ts` に `Checkpoint` を新設（`BigStory.milestones` という既存の別概念と紛れないよう、あえて別の名前にした）。

```ts
interface Checkpoint {
  id: string;
  cardId: string;                                  // GoalCard.id 必須
  title: string;
  period: { kind: "week" | "month"; start: string; end: string };
  status: "active" | "done" | "abandoned";          // 二値評価を避けた3値
  createdAt: string;
  updatedAt: string;
}
```

`status` を3値にしたのは、達成/未達成の二値評価がオール・オア・ナッシング思考を招き、少しの停滞で放棄されやすいという前回調査の知見を反映したため。`"abandoned"`（今回は終わりにする）は失敗ではなく通常の選択として扱う。

### UI設計の要点（前回調査を反映した箇所）

- 週/月の切り替えは既存チップと同じトグルボタン。切り替えると期間が自動で入り直る（毎回自分で日付を打たせない）
- 進捗は「達成率」ではなく「期間の消化率」（経過日数のバー）。中身の達成度は本人が状態ボタンで申告する
- 完了/未完了の二値ではなく「完了にする」「今回は終わりにする」「続きから戻す」の3操作
- 新規タブは作らず、既存の`/goals`と`/goal/[id]`に差し込んだ

## 仕組みの説明

1. `/goal/[id]` で「＋ 今週の中間目標を足す」を押すと、その場で下書きが1件表示される（まだ保存されない）
2. タイトルを書いて保存すると、初めて`localStorage`（`gc.checkpoints`）に書かれる
3. `/goals` の一覧では、各目標カードについて`nearestActive()`（活動中のうち期限が近いもの）を1件だけ表示する
4. 目標そのものを削除すると、`deleteCard()`が`deleteCheckpointsOfCard()`を呼び、ぶら下がる中間目標も一緒に消える。その件数は削除確認の文言に出る

### 実機で見つけて直した使いにくい点

1. **タイトル欄が不要に複数行だった**：`EditableField`に`multiline`を指定していたため、1行の見出しに対して縦に伸びるtextareaが出ていた。`HabitEditor`のタイトル欄は単行なので、それに揃えて`multiline`を外した
2. **目標削除時、中間目標が消えることを言っていなかった**：予定・習慣は件数が確認文に出るのに、中間目標だけ出ていなかった。`deleteImpactText`に`checkpoints`引数を追加した

### 見つけたが今回は直していない点（次の課題）

- **編集・削除ボタンのアクセシブルネームが同一カード内で重複する**：`EditableField`の`label`をそのまま使っているため、中間目標を2件以上作ると「今週・今月やることを編集」というボタンが2つ並び、スクリーンリーダー等では区別できない。これは`HabitEditor`にも既にある同じ形のパターンで、今回のCheckpoint固有の問題ではないため、単独では直さず据え置いた
- **Supabase同期が未対応**：`gc.checkpoints`はローカル専用。ログインしていても中間目標はクラウドへ同期されない。着手順（前回調査）の最後のステップとして残してある
