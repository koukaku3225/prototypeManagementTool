## 変更内容

### 1. 取り込みで中間目標が消える（新規発見）

**症状**：ログインして「置き換える」（または空の端末での自動取り込み）をすると、
中間目標と「建て方の評価」がすべて消える。警告は出ない。

**原因**：`pullAll()` はクラウドの中身を `restoreState()` で書き戻す。
`restoreState()` は**対象キーを一度すべて消してから**詰め直す。
中間目標（`gc.checkpoints`）はクラウドにテーブルが無いので、クラウド側から戻ってこない。
端末固有キー（打刻など）は持ち越していたが、中間目標は持ち越していなかった。

**直し方**：持ち越すキーを選ぶ処理を純粋関数 `carryOverOnPull()` に切り出し、
中間目標のうち**取り込んだ目標にぶら下がるもの**を持ち越すようにした。
親の目標がクラウドに無いものは、画面のどこからも辿れなくなるので持ち越さない
（`deleteCard()` が中間目標を一緒に消すのと同じ考え）。

### 2. R14：予定を1件だけ消した直後にタブを閉じる

**症状**：ログイン中に予定を1件消して1.5秒以内にタブを閉じると、削除がクラウドに届かない。
別端末で取り込むと、消したはずの予定が戻る。

**直し方**：`deleteTimeBoxes(ids)` を足し、書き込み1回のあとに送り切る
（`deleteCard()` と同じ `onSyncFlushHook`）。`deleteTimeBox(id)` はこれを1件で呼ぶ。
カレンダー同期の一括削除（`CalendarSyncBoot`）は1件ずつ呼ぶと**件数ぶん全件送信**が走るので、
`deleteTimeBoxes()` にまとめて渡すようにした。完了済みの習慣枠が付けた「できた」の取り消しは従来どおり。

### 3. R15 を閉じた

dc24b85 で `/big` と `/card` は `readApiResponse()` を通すようになり、
打ち切り（504・JSON でない応答）と 4xx は自動で再試行しない。再試行するのは
上流の一時的な 5xx と、通信そのものが切れたときの1回だけ。R15 の推し案（B）と同じ形になっていた。

### 4. ボタン名の重複

中間目標や習慣を2件以上作ると、読み上げでは「今週・今月やることを編集」「消す」「この習慣をやめる」が
区別できなかった。既存の `理由${i + 1}` と同じ番号付けの流儀で揃えた。

- 中間目標：各カードを `role="group"`「中間目標N」にし、「中間目標Nの今週・今月やることを編集」「中間目標Nを完了にする」「中間目標Nを消す」など
- 習慣：「習慣N」グループ、「習慣Nの繰り返すことを編集」「習慣Nの開始時刻」「習慣Nをやめる」など
- つまずき（目標詳細）：「つまずきそうなことNを編集」「つまずきNの「もし」を編集」「つまずきそうなことNを消す」

見た目の文字は変えていない（読み上げ名は見た目の文字を含む形にしてある）。

## 仕組みの説明

```
ログイン → 向きの判定が「取り込み」 / 設定で「置き換える」
  → pullAll(): クラウドから目標・習慣・予定などを取得
  → carryOverOnPull(いまの端末の状態, 取り込んだ目標のID)
       端末固有キー ＋ 取り込んだ目標にぶら下がる中間目標 を拾う
  → クラウドの中身を足して restoreState()（全部消してから詰め直す）
  → 中間目標が残る
```

予定の削除：`deleteTimeBoxes()` が localStorage を1回書き、同期の待ち行列を
その場で送り切る。ログインしていなければ待ち行列は空なので何も起きない。
