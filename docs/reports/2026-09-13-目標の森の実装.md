# 目標の森の実装

日付：2026-09-13
種別：実装
状態：完了

## 結論

シミュレーターで竜一さんが気に入った「森」表示を、アプリに入れた。

- `/goals` の「リスト／ツリー」切り替えを「リスト／森」にした。木を押すと選ばれ、下にその目標の中身と詳細への入口が出る
- `/goal/[id]` の上部に、その目標だけの木を1本出した。中間目標を完了にしたり、評価で価値観を選んだりすると、その場で枝ぶりと根が変わる

実データから描いていて、架空の値は使っていない。

## 依頼と背景

- 前回：UIを「成長する木」のメタファーでグラフィカルにしたい、という相談からモックとシミュレーターを作った（[2026-09-13-成長する木のUIデザイン案.md](./2026-09-13-成長する木のUIデザイン案.md)）
- 竜一さんが「森」版を選び、置き場所として「目標タブのトップを森に置き換える」「目標の詳細に1本の木」の2つで合意した
- 指示は「実装を進める・動作確認は必須・最後まで作る・終わったらpush」

## 変更内容

### データと見た目の対応

| 木 | アプリのデータ | 決め方 |
|---|---|---|
| 木1本 | 目標（`GoalCard`） | 進行中を作った順に並べ、その後ろに完了した目標。最大6本 |
| 木の高さ・太さ | 目標を作ってからの日数 | 112日でほぼ大人の大きさ |
| 小枝 | 中間目標（`Checkpoint`） | 1件につき1本。直近12件まで |
| 芽／花／落ち葉 | 中間目標の状態 | 期間中＝芽、完了＝花、今回は終わり＝落ち葉。期間が過ぎて未記録なら葉だけ |
| 葉の量・色 | その目標の習慣の直近30日の達成率 | 率が出せないうち（予定日3日未満）は中立にして、黄ばませない |
| 実 | 完了にした目標 | |
| 地下の根 | 大きな物語の「大事にしているもの」 | |
| 根と木をつなぐ線 | 中間目標の「たて方を評価する」で選んだ価値観 | 木ごとに和集合。根の太さは選ばれた中間目標の数 |

進み具合で枝を伸ばさないのは、シミュレーターのときに決めたとおり。手が止まった週に木が枯れたように見えると、責める見た目になるため。

### ファイル

- `src/lib/forest.ts`（新規）：実データから森のデータを組み立てる純粋関数 `buildForest`
- `src/lib/forest-draw.ts`（新規）：枝・葉・根の形を計算する純粋関数 `drawForest`。乱数は目標・中間目標の id から決めるので、開くたびに枝ぶりが変わらない
- `src/components/GoalForest.tsx`（新規）：SVGで描くだけのコンポーネント。`single` で1本表示
- `src/app/goals/page.tsx`：旧 `TreeView` を `ForestView` に置き換え。旧URL `?view=tree` も森で開く
- `src/app/goal/[id]/page.tsx`：上部に1本の木。編集中の状態（中間目標・習慣）から毎回組み立てる
- `src/app/globals.css`：森の配色（明暗両方）
- `src/app/story/page.tsx`・`src/app/tree/page.tsx`：「ツリーで見る」リンクとリダイレクト先を森へ
- `tests/forest.test.mjs`（新規）：10件。`package.json` の `npm test` に追加

## 仕組みの説明

1. 画面が localStorage から大きな物語・目標・中間目標・習慣・習慣の記録を読む
2. `buildForest` が木ごとの小枝の状態・葉の元気さ・つながる根を決める
3. `drawForest` がそれを、枝の座標・葉の向き・色などの形に変える（先へ行くほど細くなる枝、1枚ずつ色の違う葉）
4. `GoalForest` がSVGとして描く。`dangerouslySetInnerHTML` は使っていない（禁止パターンの検査も通過）
5. 詳細画面では、中間目標や評価を変えると state が変わり、木がすぐ描き直される

## 残っていること

- 竜一さんの実データ（Vercel上）で見たときの見え方の確認。中間目標が0件の目標は、梢の葉だけの細い木になる
- 中間目標が12件を超えると古い小枝は描かない（今は区切りを表示していない）
- 価値観が5つ以上あると、根のラベルが混み合う可能性がある
- Supabase同期は中間目標と同じく未対応のまま
