### R16：中間目標の同期

| 場所 | 変更 |
|---|---|
| 本番 Supabase | `checkpoints` テーブル。目標を消すと一緒に消える。RLS は本人の行のみ。user_id・card_id に索引 |
| `src/lib/supabase/mappers.ts` | `checkpointToRow` / `checkpointFromRow`。評価が無いときは null で送る |
| `src/lib/supabase/sync-decision.ts` | `mergeCheckpoints`（ローカルとクラウドを合わせる）、`sendableCheckpoint`（送れる形か） |
| `src/lib/supabase/sync.ts` | 送信・取り込み・送り直しの順序に中間目標を追加。`ensureCheckpointsMerged` |
| `src/lib/storage.ts` / `storage-keys.ts` | `replaceCheckpoints`、端末の印 `gc.checkpointsMerged` |

**気をつけたこと：最初の送信で別端末の中間目標を消さない。**
このアプリの送信は「そのキーの中身でクラウドをまるごと突き合わせ、手元に無い行はクラウドから消す」方式である。
しかも、すでに同期している端末は開くたびに全部を送り直す。
テーブルを足しただけでは、ある端末が初めて送った瞬間に、別の端末から上がっていた中間目標を消してしまう。
そこで端末ごとに最初の1回だけ、次の手順を踏むようにした。

1. クラウドの中間目標を読む
2. ローカルと合わせる：片方にしか無いものは両方残す。両方にあれば更新が新しいほう、同じならローカル
3. 合わせた結果をローカルに書き戻す
4. 送る。送れたら端末に「合わせ済み」の印を付ける。失敗したら印を付けず、次回やり直す

印が付くまでは、ふつうの送信経路でも中間目標を送らない。
形式が不正な中間目標（日付の形が違うなど）は外して送り、画面上部の帯で知らせる。1件のために全体が拒否されないようにするため。

### R12 ①：繋ぎ直しの誤爆ガード

- 連携状態の API（`/api/calendar/status`）が「連携を作った時刻」（`connected_at`）も返すようにした
- 端末の目印を「カレンダーID」から「カレンダーIDと連携した時刻」の組にした
- 判定：

| 状況 | 動き |
|---|---|
| IDが同じ | 何も外さない。目印を新しい形で書き直す |
| IDが違い、連携した時刻が前回より新しい | 本物の繋ぎ直し。これまでどおり外して作り直す |
| IDが違うのに、時刻が同じ・古い・取れない | **不審**。外さない・目印も書かない・この回の同期を見送る |
| 前回の目印が古い形（IDだけ）でIDが違う | 比べようがないので、これまでどおり繋ぎ直しとして扱う |

最後の行を不審にしなかったのは、修正前から使っている端末で本物の繋ぎ直しをしたときに、同期が永久に止まってしまうため。

### R12 ②：同期の権限切れでも案内する

- `src/lib/calendar/google.ts`：予定の作成・更新・削除とカレンダーの作成を、理由つきのエラーで投げるようにした
- `src/lib/calendar/engine.ts`：次のように返すようにした

| どこで失敗したか | 返すもの |
|---|---|
| トークンの更新（失効） | 「連携し直しが要る」 |
| 予定の取得（権限切れ） | 「連携し直しが要る」 |
| 書き込み（権限切れ） | そこで打ち切って「連携し直しが要る」。残りを叩き続けても同じ理由で失敗するだけなので止める |
| 混雑・一時的な不調 | これまでどおり「1件の失敗」として続ける |

- 案内の印：これまでは重ね表示が読めた瞬間に消していた。同期側の権限切れまで消えないよう、どちらで付いたかを持たせた
  - 値は「重ね表示」「同期」「両方」の3つ。修正前の値 `"1"` は重ね表示として読む
  - 重ね表示が読めたら重ね表示側だけ、同期が通ったら同期側だけを消す
- 時間割と設定画面は、印の種類に合わせて文言を変えた

**あわせて直したこと**：「連携し直しが要る失敗か」の判定がエラーの型の同一性（`instanceof`）だけに頼っていた。
テストで同じファイルが別モジュールとして2回読まれ、権限切れを見逃すことが実際に起きたので、名前とステータスでも判定するようにした。

## 仕組みの説明

**中間目標**：ログインした端末で中間目標を作ったり直したりすると、保存のたびに裏でクラウドへ送られる。
別の端末で最初にログインしたときや、設定の「置き換える」を押したときは、クラウドの中間目標を取り込む。
取り込むとき、その端末がまだ一度もクラウドと合わせていなければ、手元の分も残す。

**カレンダー**：時間割を開くと、送る前に連携状態を確認する。
カレンダーIDと連携した時刻を前回の目印と比べ、本物の繋ぎ直しのときだけ古い紐づけを外す。
送った結果が権限切れなら印を付け、時間割の上と設定画面に「連携し直してください」を出す。
