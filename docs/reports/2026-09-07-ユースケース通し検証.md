# ユースケースを通しで触って見つけた、想定と違う挙動

日付：2026-09-07
種別：調査
状態：完了（コードは一切変更していない）

## 結論

まっさらな状態から「目標を決める → 予定を作る → こなす → 振り返る」までを実際に通した。
**時刻の編集まわりは直っていた**が、想定と違う挙動が **9件** 見つかった。

いちばん重いのはこれである。

> **目標を1つ消したら、その目標にぶら下がっていた予定2件・習慣1件・達成記録1件が
> すべて一緒に消えた。確認画面には「この目標を消します。戻せません。」としか出ない。**

書いた振り返りごと消える。しかも同じアプリの予定シートは
「この予定を消します。**振り返りも一緒に消えます**」と、ちゃんと巻き添えを書いている。
片方だけ書いていない。

## 検証のやり方

本番（`https://prototype-management-tool.vercel.app`）を、localStorage が空の
新しいブラウザで開いた。画面サイズは 375×812（スマホ相当）。ログインはしていない。

**制約**：このセッションは定期タスクとして起動したため、`npm run dev` を立ち上げられず、
またブラウザペインを表示できなかった。そのため指でのタップやドラッグではなく、
**JavaScript 経由でクリックとフォーム入力を発火させて操作した**。
React は合成イベントを同じように扱うので画面の反応は同じだが、
**ドラッグでの移動・リサイズと、実機のネイティブ日時ダイアログの挙動は検証できていない。**

## 想定と違った挙動（重い順）

### ★1 目標を消すと、予定・習慣・達成記録が黙って全部消える

**やったこと**：目標「副業」（予定2件・習慣1件・習慣の達成記録1件がぶら下がっている）を消した。

**想定**：目標カードが消える。予定は残るか、消えるなら「予定も消えます」と言われる。

**実際**：

```
消す前: { cards:1, boxes:2, habits:1, logs:1 }
消した後: { cards:0, boxes:0, habits:0, logs:0 }
```

完了済みの予定に書いた振り返り（できばえ75%・「次はスマホを別の部屋に置く」）も
一緒に消えた。確認文は「この目標を消します。戻せません。」だけ。

**原因**：`src/lib/storage.ts:471-480` の `deleteCard()` は、意図して連鎖削除している。

```ts
export function deleteCard(id: string): void {
  write(KEY.cards, loadCards().filter((c) => c.id !== id));
  // ぶら下がっていた習慣・記録・予定も一緒に消す。残すと孤児になり、
  // 「どの目標のためだったか」が二度と分からなくなる
  deleteHabitsOfCard(id);
  deleteTimeBoxesOfCard(id);
}
```

**処理は設計どおり**で、間違っているのは**確認文**（`src/app/goal/[id]/page.tsx:513`）。
実際の破壊範囲を書いていない。同じアプリの `TimeBoxSheet.tsx` は
「この予定を消します。振り返りも一緒に消えます。」と巻き添えを明記しているので、
基準が揃っていない。

---

### ★2 「今日の予定」リストが時刻順に並ばない

**やったこと**：21:00の習慣と23:00の予定がある状態でリスト表示を開いた。

**想定**：21:00 → 23:00 の順。

**実際**：23:00 が上、21:00 が下（「過ぎています」付き）。

**原因**：`src/app/list/page.tsx:75`

```ts
setBoxes([...timeBoxesOn(today()), ...habitBoxesOn(today(), hs, loadTimeBoxes())]);
```

`timeBoxesOn()` は開始時刻で整列するが（`storage.ts:583-586`）、そのうしろに
習慣の枠を**足しているだけ**で、合わせたあとに並べ直していない。
つまり「実体の枠 → 習慣の枠」が常にこの順になり、時刻は無視される。

時間割（DayGrid）は時刻で位置を決めるので影響が出ず、リスト表示にだけ出る。
リスト表示は昨日（`529ba35`）足したばかりの画面である。

---

### ★3 「短い呼び名」を付けても、目標一覧とリストでは長文が出る

**やったこと**：目標に短い呼び名「副業」を設定した。
入力欄の説明にはこう書いてある ——
「時間割で『どの目標のためか』を選ぶときに、ここで付けた名前が短く表示されます」。

**想定**：目標の名前として「副業」が使われる。

**実際**：短い呼び名が効くのは**予定シートのプルダウンだけ**。

- 目標一覧（/goals）：「半年後、副業で月5万円を安定して稼げている状態」
- リスト（/list）の各行：同上
- わたし（/me）の「続いていること」：同上

**原因**：`goalCardLabel()` を呼んでいるのは2箇所しかない。

```
src/components/RunningBar.tsx:91
src/components/TimeBoxSheet.tsx:255
```

`/goals`・`/list`・`/me`・`/card`・`WeekShareBar` は `vision.refined` を直接描いている
（例：`src/app/list/page.tsx:211-212`）。

説明文どおりではあるが、**呼び名を付けた人は「この目標の名前を決めた」つもりでいる**。
一覧で長文のままなのは想定外に感じる。

---

### ★4 「完了」にした目標の習慣が、時間割に並び続ける

**やったこと**：目標を「この目標を完了にする（枠が空きます）」で完了にしたあと、
翌日の時間割を開いた。

**想定**：完了した目標の習慣は、もう並ばない（か、何か断りが出る）。

**実際**：習慣「毎晩コードを書く」は翌日も 21:00 に並んだままだった。
一方で、予定シートの「どの目標のためか」からは選択肢が消えていた（「（紐づけない）」だけ）。

つまり **並んではいるが、紐づけ直すことはできない** 状態になる。

**原因**：選択肢は目標の `status !== "done"` で絞っているのに、
`habitBoxesOn()` は目標の状態を見ておらず、習慣の `archivedAt` だけを見ている。
目標を完了にしても習慣は自動でアーカイブされない。

---

### ★5 完了した目標に紐づく予定を開くと、「（紐づけない）」と表示される（データは紐づいたまま）

**やったこと**：目標を完了にしたあと、その目標に紐づく予定を開いた。

**想定**：紐づいている目標名が出る（完了済みなら、そう分かる形で）。

**実際**：

```
画面の選択:        （紐づけない）
選択肢:            ［（紐づけない）］のみ
保存されているcardId: e613ea23-...（紐づいたまま）
```

画面が嘘をついている。ここで別の項目（タイトルなど）を触ると保存が走るが、
`cardId` は書き換わらないので、**表示は「紐づけない」なのに実データは紐づいたまま**が続く。

**原因**：`<select value={draft.cardId}>` に対応する `<option>` が無いとき、
ブラウザは先頭（＝「（紐づけない）」）を選択状態として描く。
`TimeBoxSheet` は `cards` を親から受け取るだけで、
「いま紐づいている目標が選択肢に無い」場合の面倒を見ていない。

---

### ★6 「時間割で予定を作る →」から行っても、その目標が引き継がれない

**やったこと**：目標画面の「時間割で予定を作る →」を押し、そのまま予定を作った。

**想定**：その目標のために時間を取りに来たのだから、目標は最初から紐づいている。

**実際**：「（紐づけない）」のまま。プルダウンから選び直す必要がある。

**原因**：リンク先が素の `/plan`（`href="/plan"`、目標IDを渡していない）。
`/plan` 側にも目標を受け取る口が無い。

目標 → 予定 という、このアプリの中心の導線でここが切れている。

---

### ★7 「手入力でつくる」を押した瞬間に、空の目標が保存される（習慣も同じ）

**やったこと**：`/goal/new` で「手入力でつくる（AIを使わない）」を押した。

**想定**：入力画面が開く。保存するかどうかは自分が決める。

**実際**：押した瞬間に目標カードが localStorage に書き込まれた。

```json
{"id":"e613ea23-...","vision":{"raw":"","refined":""},"status":"active", ...}
```

全項目が「（未記入）」の目標が1枠を占める（目標は3枠まで）。
「＋ 繰り返すことを足す」も同じで、押した瞬間に `title:""` の習慣が保存される。

**原因**：押下時に `emptyCard()` / 空の習慣をそのまま保存している。

同じ問題を予定シートでは既に直している。`TimeBoxSheet.tsx` のコメント：

> 以前は空きを押した瞬間に枠を作っていたので、間違って触っただけで
> 「（未記入）」が残った。作るのは「この時間に入れる」を押したときだけ。

**その学びが、目標と習慣には適用されていない。**

---

### ★8 ログインしていなくても、Googleカレンダー連携ボタンが押せる

**やったこと**：ログインしない状態で `/settings` を開いた。

**想定**：カレンダー連携はクラウド前提なので、先にログインを促される。

**実際**：「クラウド同期：ログインする」の下に、そのまま
「Googleカレンダーと連携する」ボタンが出ている。

**原因**：`src/app/settings/page.tsx:236` は `<CalendarLink />` を無条件に描いており、
`CalendarLink.tsx` 自身もログイン状態を見ていない。
`/api/calendar/connect` の `requireAuthIfEnabled()` は `REQUIRE_AUTH=true` のときしか
効かず、本番では未設定である（`/api/calendar/status` が401ではなく
`{"connected":false,...}` を200で返すことで確認した）。

このまま進むと、Googleの同意画面まで通したあとに `saveLink()` が
ユーザー不在で false を返し、`/settings?calendar=save` に落ちる。
**未検証**：実際に同意まで進める操作はしていない（Googleアカウントへの権限付与になるため）。
コードを読んだ範囲での推定である。

### ★9 細かい表記のズレ

- `aria-label="何をを編集"` — 助詞が重なっている（`何を` + `を編集`）。読み上げで不自然
- `/settings`：「内部計測を見る（M1〜**M7**）」／`/me`：「内部計測 開発用。M1〜**M8**」
- `/me`：習慣を完了した直後でも「はじめて**0**日目。14日たつと、続き具合をここに出します。」
  と出る。記録はされているが、押した手応えが画面に返らない

念のため疑って確かめたが、設計どおりだったものを挙げておく。
