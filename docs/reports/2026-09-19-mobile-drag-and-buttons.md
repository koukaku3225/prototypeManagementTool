# スマホの時間割操作の改善と、完了／閉じるの入れ替え

日付：2026-09-19
種別：修正
状態：完了（ローカルで実機相当の操作を再現して確認、本番へ反映済み）

## 結論

- 予定シートの主操作を **「完了にする」＝左、「閉じる」＝右** に入れ替えた。無意識に触りやすい右側が、取り消しづらい完了ではなくなった。
- スマホでドラッグが効かなかった原因は **ポインタイベントの `preventDefault()` ではスクロールを止められない** ことだった。長押しで掴んだ直後に指を動かすと時間割がスクロールし、ブラウザがドラッグを取り上げていた。`touchmove` を止める形に直した。
- あわせて、指の「ふつうのタップ」（220〜500ms）が長押しに化けて **予定が開かなくなる** 問題と、指のぶれ数pxが「移動」と数えられる問題も直した。

## 依頼と背景

1. 完了と閉じるが逆で、無意識に右を押して完了してしまう。
2. PCのマウス操作は問題ないが、スマホのタップ＆リリース・長押し移動の操作感が悪い。

## 変更内容・調査結果

### 原因（スマホのドラッグ）

| # | 症状 | 原因 |
|---|---|---|
| 1 | 長押しで掴んでも、指を動かすと枠が動かず画面がスクロールする | ドラッグ中は `pointermove` で `preventDefault()` していたが、**ポインタイベントではスクロールは止まらない**。指の操作をスクロールに使うかは `touch-action` と `touchmove` で決まる。`touch-action` は指を置いた瞬間の値で確定するので、長押し成立後に `none` へ切り替えても、そのジェスチャーには効かない。結果、スクロールが始まり `pointercancel` でドラッグが消えていた |
| 2 | 枠を軽くタップしても予定が開かないことがある | 長押しの成立は220ms。指のタップは250ms前後になることが多く、長押し扱いになって直後の click が「ドラッグ直後」として捨てられていた |
| 3 | 押しただけで保存が走る | 押している間の数pxのぶれを「動かした」と数えていた |
| 4 | タップ直後の click が捨てられることがある | click を捨てるかの判断が React の状態（`dragging`）を見ており、pointerup 直後はまだ古い値だった |

### 直した内容

- `useGridDrag` に `touchmove` の監視（`passive:false`）を足し、ドラッグ中だけスクロールを止める。長押し成立まで指は10px以内なので、スクロールが始まる前に間に合う。
- 「押して離した」の意味を純粋関数 `pressOutcome()` に切り出した（`src/lib/grid-gesture.ts`）。動かした＝確定、動かさず短い押し＝タップ（予定を開く）、動かさず500ms以上＝つかんだだけ（選択を残す）。
- 指のぶれは `isRealMove()`（4px）で除外。
- click を捨てる判断を、状態ではなく参照（`isDragging()`）で行う。
- 指の捕捉先を `e.target` から枠自身（`currentTarget`）へ。つまみが描き直しで消えても捕捉が外れない。
- 枠に `-webkit-touch-callout: none` と `user-select: none` を明示。長押しで iOS の拡大鏡・コピーメニュー、Android の文字選択が出るのを防ぐ。
- 予定シートの「完了にする」と「閉じる」を左右入れ替え（新規作成時の「やめる／この時間に入れる」は、取り返しのつく操作なので変更していない）。

## 仕組みの説明

スマホのブラウザは、指が触れた瞬間に「この指はスクロール用か、ページの操作用か」を決めます。決め方は要素の `touch-action` で、あとから変えても、その指の操作には反映されません。今回のアプリは「長押ししてから掴む」ので、掴んだ時点ではもう「スクロール用の指」として扱われていました。唯一の対抗手段が `touchmove` を止めることで、これは指が実際に動き始めた最初の1回で判断されるため、長押しのあとでも間に合います。

## 確認したこと

ローカルの開発サーバーをスマホ幅（375×812・タッチ端末として）で開き、架空の枠2件を入れて**実際のタッチイベント列**（touchstart/touchmove/touchend＋pointer）で操作した結果：

| 操作 | 結果 |
|---|---|
| 枠を250msタップ | 予定が開く（修正前は開かなかった） |
| 長押し→下へ56pxドラッグ | 10:00〜11:00 → 11:00〜12:00 に移動。ドラッグ中の `touchmove` は4回とも抑止（＝スクロールに奪われない） |
| 長押し650ms・動かさない | つまみが2つ出て、予定は開かない |
| 押してすぐ動かす（スクロール意図） | `touchmove` は抑止されず、枠も動かない |
| 3pxのぶれ | 時刻は変わらず、タップとして予定が開く |
| つまみを引く（指） | 11:00〜12:00 → 11:00〜12:30 |
| 空きを長押しして引く | 17:00〜18:00 の新規シートが開く |
| マウスでドラッグ／クリック | これまでどおり移動・予定が開く |

- 予定シートのボタン位置をDOM上で確認：完了にする（左 x=16）、閉じる（右 x=235）。
- `npm test` 全件成功（grid-gesture 6件を追加）。`tsc --noEmit` エラーなし。`npm run build` 成功。
- 本番：push → Vercel 反映後に本番URLで確認（下記「本番」）。
- 検証に使ったブラウザは未ログインで、クラウド同期は動いていない。検証用の枠は削除済み。

## 残っていること

- 実機（竜一さんのスマホ）での体感確認。ブラウザのタッチ端末エミュレーションで同じイベント列は再現したが、実際の指の動き・慣性スクロールまでは再現していない。
- 長押しの時間（220ms）とタップの上限（500ms）は今回の値が最適とは限らない。実機で「タップのつもりが選択になる」「長押しが待たされる」と感じたら調整する。
