## 改善1（最優先・実施済み）: 対話で決めた「どこでやるか」が、明日の一歩の枠から消える

### 現在の問題

いつ・誰が・何に困るか：
**目標対話を最後までやり切った利用者**が、`woop_wbs`（障害と明日の一歩）フェーズで
コーチに促されて「明日7時に、自室の机で」のように**場所まで具体に決めても、
その『どこで』が時間割の枠に残らない**。当日その枠を開いても時刻とタイトルだけで、
「どこでやるんだっけ」をまた考えることになる。

`woop_wbs` の指示文は場所の具体化を明記している
（`src/lib/prompts/phases.ts:181`「『家で』なら『家のどこですか』まで具体にする」、
同 `184-187`「やることだけ決めて時間と場所を決めないと、当日に『いつやるか』を
もう一度考えることになり、そこで止まる」）。その設計思想の半分が、
枠を作る所で捨てられていた。

### 根拠

- `src/app/card/page.tsx` の `confirm()`（修正前）は、枠の `meta.counter` を
  こう組み立てていた：
  ```ts
  counter: firstObstacle?.plan.if
    ? `もし${firstObstacle.plan.if} → ${firstObstacle.plan.then}`
    : (t.where ? `場所: ${t.where}` : ""),
  ```
  **If-Then と「場所」が二者択一**で、If-Then がある側に倒れると `t.where` は行き場が無い。
- `woop_wbs` は完了条件に「障害1件」を含む（`src/lib/prompts/phases.ts:196`）ので、
  対話を通した枠には**ほぼ必ず `firstObstacle` が入る** → `t.where` は**ほぼ必ず捨てられる**。
- `t.where` は `card/page.tsx` の中でしか参照されず、`GoalCard` にも保存されない
  （`built` に `tasks` は含まれない）。枠に入らなければ**その場で永久に消える**。
- 抽出プロンプトは場所を要求している（`src/lib/prompts/extraction.ts:119`
  「where: 本人が言った場所をそのまま短く。『自室の机』『近所の体育館』」）。
  取った値を使っていなかった。

### 提案（最小限）＝ 実施した内容

`meta` の組み立てを純粋関数に切り出し、If-Then と場所を**両立**させた。

- `src/lib/goal-card.ts` に `firstStepMeta({ rationale, vision, obstacle, where })` を追加。
  `counter` は `[If-Then, "場所: …"]` を改行でつなぐ（空の項目は落とす）。
  **`where` が無いときの出力は従来と1文字も変わらない。**
- `src/app/card/page.tsx` の `confirm()` は、この関数を呼ぶだけにした。

### 優先する理由

- **対話の成果（30〜40分かけて言語化したもの）を捨てない。** これはアプリの
  中心価値「具体的な行動に移れる」の一部で、「どこで」は"具体"の要素。
- 変更は純粋関数1つ＋呼び出し1箇所。回帰は総当たりのテストで固定できる。
- 追加のみ（いま捨てている情報を残すだけ）なので、既存の完了・振り返り・
  同期の挙動には影響しない。

### 完了条件

- [x] 障害がある枠でも、対話で決めた場所が `meta.counter` に残る。
- [x] 場所が未取得（`null`・空白）のときの `counter` は従来と同一。
- [x] `npm test` / `npx tsc --noEmit` / `npm run build` がすべて通る。

### 確認方法

- 単体：`tests/goal-card.test.mjs` に `firstStepMeta` の8件を追加（26→33件）。
  「障害＋場所 → 両方 counter に残る」「場所 null → If-Then だけ（従来どおり）」
  「空白だけの場所は書かない」など。うち「障害があっても場所が捨てられない」は
  修正前のロジックでは落ちる回帰テスト。
- 手動（未実施・課金が発生するため）：対話を `woop_wbs` まで通し、
  場所を答えて確定 → `/goal/<id>` から明日の枠を開く →
  「対策は」欄に If-Then と「場所: …」が両方見えることを確認。

### 規模

**小**。変更対象：`src/lib/goal-card.ts`（純粋関数追加）、
`src/app/card/page.tsx`（呼び出しに置換）、`tests/goal-card.test.mjs`。

## 改善2（判断待ち）: インライン編集の1文字ごとに、クラウドへ全時間割を送っている

### 現在の問題

**ログイン中の利用者**が、予定シート（`TimeBoxSheet`）で
「何をやるか」「始める前に決めておく」「振り返り（よかったこと／悪かったこと／
今後の対策、各最大500字）」を打つと、**1キーストロークごとに
`gc.timeboxes` の全行が Supabase に upsert される**。

3文の振り返りを書くだけで、数十〜百回超の全件送信が数秒間に走る。
モバイル回線が一瞬詰まると、そのうち1回が失敗して
「クラウドへの保存が止まっています」の帯が出る。localStorage 側は
問題なく保存できていて、次のキーストロークで自己回復するが、
**帯が理由なく明滅する**のは「壊れているのか」という不安につながる。

### 根拠

- `src/components/TimeBoxSheet.tsx:93-97` `patch()` は、既存の枠なら
  `onSave(next)` を**毎回**呼ぶ（「項目が少ないので保存を押させない」という
  意図的なUX）。時刻欄だけは `applyTime()`（同 `110-114`）で
  「値が変わったときだけ」に絞っているが、**自由記述の欄は絞っていない**。
- `onSave` → `upsertTimeBox` → `src/lib/storage.ts:135` `write()` →
  `onWriteHook`（`pushKey`）を**同期で無条件に呼ぶ**。デバウンスは無い。
- `src/lib/supabase/sync.ts:298` `pushKey` もデバウンスせず、
  `reconcileCollection()` は配列を**1回の `upsert(rows)` で全行送る**（同 `186` 付近）。
- 失敗すると `noteFailure`（同 `315`）→ `SyncStalledBar` が出る。
- 対比：`src/components/EditableField.tsx` は「保存」ボタンで1回だけ、
  `src/components/LocalBackupBoot.tsx` はディスク書き込みを4秒デバウンス済み。
  **クラウド同期だけが素通し。**

### 提案（最小限）

`write()` から `onWriteHook`（＝ `pushKey`）を呼ぶ所に、**キー別の
末尾デバウンス（1.5〜2秒程度）**を挟む。localStorage への書き込みは
今までどおり同期のまま（データ消失リスクを増やさない）。
`visibilitychange` / `pagehide` で保留分を即フラッシュする。

- 純粋な `createKeyedDebouncer()` を作り、`tests/` で
  「同じキーの連打は最後の1回だけ」「別キーは独立」「フラッシュで即発火」を固定。
- `LocalBackupBoot` が既に4秒デバウンスなので、2秒は整合的。

### なぜ判断を委ねるか

- `write()` は**このリポジトリで最も中心的な関数**で、同期テスト
  （`sync-decision` `sync-bar` `storage`）の前提に触れる。
- デバウンス窓の中でタブが強制終了されると、**クラウドがローカルより
  一瞬遅れる**。ローカルには残るが、次に `gc.timeboxes` を書くまで
  クラウドは古いまま＝別端末で古い振り返りが見える。
- `AGENTS.md` の「localStorage が丸ごと消えた実例」の重さからも、
  同期タイミングの変更は本人が納得してから入れるべき。

### 完了条件（実装したときに満たすべきもの）

- [ ] 振り返りを1本書いても、Supabase への `timeboxes` upsert は
  タイプが止まってから1回だけになる。
- [ ] タブを閉じる／隠すと、保留分が即送信される。
- [ ] `SyncStalledBar` は、実際の失敗のときだけ出る。
- [ ] 既存の同期テストが引き続き通る。

### 確認方法

- 単体：`createKeyedDebouncer` の総当たり。
- 手動：DevTools の Network で `rest/v1/time_boxes` の呼び出し回数を、
  振り返り記入前後で比べる。ログインして別ブラウザで同じ振り返りが見えること。

### 規模

**中**。変更対象：`src/lib/storage.ts`（または同期フックの薄いラッパを新設）、`tests/`。

## 改善3（判断待ち）: 習慣から並んだ枠に、メタ認知が一切載らない

### 現在の問題

習慣（曜日＋開始時刻を持つもの）は時間割に自動で並ぶが、
その枠の `meta` は常に `emptyMeta()`（空）。
習慣自体は「どこでやるか」（`Habit.where` / DB `location`）を持っているのに、
**実際に行動する場所である時間割の枠には出てこない**。

改善1と同じ症状（決めた「どこで」が行動の直前に読めない）が、
対話由来だけでなく習慣由来の枠にも出ている。習慣は毎日・毎週くり返す
＝読み返しの回数がいちばん多い枠なので、影響はむしろこちらが大きい。

### 根拠

- `src/lib/habit-plan.ts:121` `habitBoxesOn()` … 起こす枠に必ず `meta: emptyMeta()`。
- `src/types/behavior.ts:43` `Habit.where` は存在し、
  `src/lib/supabase/mappers.ts:145` で `location` として同期もされている。
- 習慣編集画面（`HabitEditor`）には場所の入力があるが、
  時間割の枠・`TimeBoxSheet` からはその値に辿り着けない。

### 提案（最小限）

`habitBoxesOn()` が起こすゴースト枠の `meta.counter` に、
`habit.where` があれば `場所: …` を入れる（`firstStepMeta` と同じ書式）。
実体化（`materializeHabitBox`）後は本人が自由に上書きできる。

将来的には「なぜ重要か」「障害」「対策」も習慣に持たせて枠へ流す拡張が考えられるが、
`Habit` 型に項目を足す話になるので、まず `where` だけを繋ぐ。

### なぜ判断を委ねるか

- ゴースト枠は**表示のたびに再計算される**もので、実体化前は保存されない。
  そこに `meta` を入れると「触っていないのに中身がある枠」になり、
  `TimeBoxSheet` の「中身があるときだけ『始める前に決めておく』を開く」
  （`hasMeta`）の挙動に影響する。開いた状態で出したいのか、
  畳んだまま値だけ持たせたいのかは、実機で見て決めたい。
- 改善1が入った直後なので、両方まとめて1回のレビューで見てもらうほうが早い。

### 完了条件（実装したときに満たすべきもの）

- [ ] 場所を設定した習慣の枠を開くと、時間割からその場所が読める。
- [ ] 場所を設定していない習慣の枠は、従来どおり空。
- [ ] `tests/habit-plan.test.mjs` に「where あり → counter に反映」「where なし → 空」。

### 確認方法

- 単体：`habitBoxesOn()` の出力を検証（既存テストと同じ形）。
- 手動：習慣に「近所の体育館」を設定 → 翌日の時間割の枠を開く → 場所が見える。

### 規模

**中**。変更対象：`src/lib/habit-plan.ts`、必要なら `TimeBoxSheet` の `hasMeta` 周り、`tests/`。

## 仕組みの説明（改善1）

対話を完了すると `/session` が `/card` へ遷移し、`/card` が
`/api/structure` に会話全文を渡して「なりたい姿」「何を」「どれくらい」
「明日の一歩（タイトル・所要時間・開始時刻・場所）」の下書きを受け取る。

本人が言い方を選んで「これで確定する」を押すと、`confirm()` が

1. `GoalCard` を保存し、
2. **明日の一歩を時間割の枠（TimeBox）として1件作る**。
   このとき WOOP の障害・If-Then を枠の `meta` へ流し込む
   （その時間になってから思い出すのでは間に合わないため）。

改善1は、この 2 で `meta.counter` を作る式が
「If-Then か、場所か」の二者択一だったのを、
`firstStepMeta()` に切り出して**両方入れる**ようにした変更。

```
修正前:  counter = 障害があれば If-Then / 無ければ「場所: …」
修正後:  counter = [If-Then, 「場所: …」] のうち中身のあるものを改行でつなぐ
         （場所が無ければ修正前と同一の出力）
```
