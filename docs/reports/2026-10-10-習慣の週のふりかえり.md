# 習慣の「週のふりかえり」を足す

日付：2026-10-10
種別：実装
状態：ローカルで動作確認済み・DB適用済み。本番の確認は push 後（末尾の「確認できていないこと」を参照）

## 結論

習慣タブ（`/habits`）から開ける「週のふりかえり」画面（`/habits/week?w=2026-10-05`、`w` は週の月曜）を足した。
1週間の数字（習慣の記録・最小版・できなかった回数・できばえ平均）を並べ、
「うまくいったこと」と「来週の自分へ」の一言を書ける。書いた「来週の自分へ」は、次の週に
「前回の自分から」として出る。保存する新しいデータは `gc.weeklyreviews`（localStorage）と
Supabase の新テーブル `weekly_reviews` だけ。数字は読んで並べるだけで保存しない。

## 背景

習慣機能パターン集（`docs/mocks/2026-10-10-習慣機能パターン集.html`）の「5 見直し・定着」から
V2「週のふりかえり」が選ばれた。直前の段（習慣の作る形・月の見開き）の続き。

## 仕組み

### 数字の数え方（`buildWeekSummary`）

数え方は `habit.ts` / `habit-month.ts` と同じ約束に揃えた（別の数え方だと画面ごとに率が食い違う）。

- 週は月曜始まり。月またぎ・年またぎは日付の足し算（`date.ts`）で扱う。
- **習慣の記録（やった＋最小版／予定された回数）**:
  - 日で数える習慣は予定日が分母。休みは外す。今日の未記録・まだ来ていない日は入れない。予定外の日の記録は回数には数えるが、率の分子には入れない（別行で「決めた曜日以外にやった」と出す）。
  - 週N回（`countsByWeek`）は週の目安が分母、1週の分子は目安で頭打ち。作った週と、畳んだ日をまたぐ週は入れない。
  - **始めて14日未満（`isWarmingUp`）の習慣は、この割合に入れない**。画面にも「入れていません」と書く。判断の基準日は今日ではなく「その週の終わり（または今日）」。
  - 最小版・できなかった・休みの回数は事実の記録なので、立ち上がり中の習慣も数える。
- 出す習慣: 進行中は、その週の終わりより前に作っていれば出す。畳んだ・完了した目標の習慣は、その週に記録があるときだけ。
- **できばえ平均**: 週の枠の `review.score`（0〜100 の有限な数）が入っているものだけの平均を整数に丸める。1件も無ければ欄ごと出さない。
- 分母が0のときは「0%」と出さず「—」。

### 前回の自分から

直前の週（`weekStart - 7日`）の「来週の自分へ」だけを出す。無い・空なら出さない。もっと前の週の一言は
出さない（古い一言を今週の言葉として見せると、書いた当時の文脈とずれるため）。

### 入力できる週

今週と過去の週は書ける。未来の週は見られるが、入力欄は出さない（まだ終わっていない週に
「ふりかえり」を書かせない）。`?w=` が月曜でない日付ならその週の月曜に丸め、壊れた値・実在しない日付・範囲外は今週に戻す。

### 保存データ

- キー `gc.weeklyreviews`: `[{ weekStart, good, nextNote, updatedAt }]`。週で一意。2欄とも空なら行を消す（空の行を作らない）。1欄は1000文字で切る。
- 読むときは `normalizeReviews` を通し、実在する月曜でない行・空の行を捨て、同じ週は新しいほうを残す。
- 2つの欄は別々に保存される。保存時は画面の持っている値ではなく、保存されている値と合わせるので、片方が古い値でもう片方を上書きしない。
- スキーマ移行（`MIGRATIONS`）は足していない。キーが無ければ空配列として読めるので、古いデータを書き換える必要が無く、`SCHEMA_VERSION` は上げない（コメントにも理由を書いた）。
- 同期端末の判定（`hasUserContent`）は端末固有キー以外を全部数える作りなので、新キーは自動で「中身」になる（テストで固定）。`resetAll()` は `KEY` の全値を消す。`SNAPSHOT_TARGETS` には明示的に足した。

### クラウド同期

- `habit_logs` と同じ「複合主キーの専用突き合わせ」（`reconcileWeeklyReviews`）。基準（`pushBase`）との差分だけを書き、この端末で消した行だけを消す。基準が無いときは全部書いて何も消さない。
- 送れない行（月曜の日付でない）は書く側から外すが「この端末にある」側には残す。外すと、クラウドの同じ週の行を「この端末で消した」と取り違えて消すため。1件の不正で配列全体の upsert が拒否されるのも防ぐ。
- 取り込み（pull）と開いたときの合体（merge）に対応。合体は `updatedAt` の新しいほうを採り、同じ・不明なら端末側。収束する（再読み込みを繰り返さない）ことをテストで確認。
- `cloudHasContent` にも `weekly_reviews` を足した。ふりかえりだけがクラウドにある新しい端末でも、空を送らず取り込む向きになる。
- **空の端末がクラウドを消す事故の不変条件は変えていない**（`decideSyncDirection` は無変更。`sync-decision` の総当たり表と `forbidden.test.mjs` の構造検査が通る）。
- サーバー側 MCP（`src/lib/mcp/*`）には出していない。

## DBの変更

Supabase `jvtfxrzpqtlqukxtftjn` に `apply_migration`（名前 `weekly_reviews`）で適用。追加のみ。

```sql
create table if not exists public.weekly_reviews (
  user_id uuid not null default auth.uid() references auth.users(id),
  week_start date not null,
  good text not null default '',
  next_note text not null default '',
  updated_at timestamptz not null default now(),
  primary key (user_id, week_start)
);
alter table public.weekly_reviews enable row level security;
create policy "own rows only" on public.weekly_reviews
  for all using ((select auth.uid()) = user_id) with check ((select auth.uid()) = user_id);
```

適用前に `habit_logs` / `habits` のポリシーを `pg_policies` で読み、同じ形（`own rows only`・ALL・`(select auth.uid()) = user_id`）に揃えた。

適用後に読み取りで確認:

| 確認 | 結果 |
|---|---|
| テーブルの有無（適用前） | 無し（`pg_class` に行なし） |
| RLS | `weekly_reviews` は有効（`habit_logs` と同じ） |
| ポリシー | `own rows only` / ALL / 条件 `((select auth.uid()) = user_id)`（using・with check とも）。`habit_logs` と文字列まで一致 |
| 列 | user_id uuid not null default auth.uid()、week_start date not null、good / next_note text not null default ''、updated_at timestamptz not null default now() |
| 制約 | 主キー (user_id, week_start)、user_id → auth.users(id) |
