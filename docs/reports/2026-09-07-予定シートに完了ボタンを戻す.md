# 予定シートから「完了にする」が押せない問題を直す

作成日: 2026-09-07
対象: `src/components/TimeBoxSheet.tsx`
ブランチ: `main`（作業ツリーはこの変更のみ）

## 結論

時間割（`/plan`）で枠をタップして開く予定シートに、**未完了の予定を「完了にする」操作が無かった**。
過ぎた予定・先の予定は、リスト表示に切り替えない限り時間割から完了にできなかった。
シートのフッターに「完了にする」を主操作として戻した。

## 背景（どの場面で誰が困るか）

- スマホで時間割を開き、19:00〜19:30「仕事終わり振り返り」（すでに20:11で過ぎている）を
  タップ → シートに「この予定を消す」と「閉じる」しか無く、完了にできない、という報告。
- 完了の入口は当時 2つだけ:
  1. リスト表示（`/list`）のチェックボックス
  2. 画面下の「いまの時間」バー（`NowBar`）
- `NowBar` が出すのは `current ?? next`。`next` は **60分以内に迫った予定**だけ
  （`nextBox(boxes, nowMinutes, 60)`）。**過ぎた予定と、61分以上先の予定はどちらにも出ない。**
- 既定表示は時間割なので、リストへ切り替えることを知らない・面倒だと、
  「終わったのに完了にできない」状態になる。中心価値（時間割で行動を管理して完了させる）が
  既定操作の範囲内で完結していなかった。

## 原因

コミット `2be35d7`（2026-09-06「予定シートの主操作を『閉じる』にし…」）が、
シートのフッターから「完了にする」ボタンを削除した。理由は
「完了はホーム画面の一覧と、時間割の『いまの時間』バーから押せるので操作が失われない」。

この前提が誤り。上記のとおり `NowBar` は進行中／直前の枠しか出さない。
`src/app/plan/page.tsx` の `save()` のコメントには削除後も
「完了は『シートの完了ボタン』『行のチェック』『いまの時間バー』のどこからでも押せて」と
残っており、コード側は「シートに完了ボタンがある」前提のままだった。

## 変更内容

`src/components/TimeBoxSheet.tsx` のフッター、既存予定（`!isNew`）の分岐だけを変更。

- **未完了のとき**: 「閉じる」（副・枠線）＋「完了にする」（主・インディゴ塗り）の横並び。
  新規予定の「やめる／この時間に入れる」と同じ 1:2 の並び。
- **完了済みのとき**: これまでどおり「閉じる」1つ（振り返りの入口は本文側にある）。
- 「完了にする」は `patch({ completedAt: 今, review: 既存 ?? emptyReview() })` を呼ぶだけ。
  `patch` は既存予定なら `onSave` を通すので、保存経路・習慣ログ連動
  （`plan/page.tsx` の `save()`）・ゴースト枠の実体化は既存のまま通る。
- 振り返り画面は自動で開かない（`NowBar` からの完了と同じ挙動。
  完了後に本文の「振り返りを書く / 直す」から入る）。
  ゴースト枠は完了時にIDが変わり `useEffect([box.id])` が走るため、
  自動遷移させると振り返り画面が即閉じる。開かない方が確実。

削除（`2be35d7` が同時に行った「消す」を「閉じる」直前へ・赤字・面を張らない）は維持。

## 仕組み

| 予定の状態 | シートのフッター |
|---|---|
| 新規（未保存） | やめる / この時間に入れる |
| 既存・未完了 | この予定を消す ／ [閉じる] [完了にする] |
| 既存・完了済み | この予定を消す ／ [閉じる]（本文に「振り返りを書く」「完了を取り消す」） |
| 習慣の予定・未完了 | [閉じる] [完了にする]（消すは無し。完了で実体化し習慣も記録） |

## 関連ファイル

- `src/components/TimeBoxSheet.tsx` — 変更箇所（フッター `!isNew` 分岐）
- `src/app/plan/page.tsx` — `save()` が完了時の保存・習慣ログ・実体化を担う（変更なし）
- `src/components/NowBar.tsx` — もう一つの完了入口。60分窓の制約はそのまま（変更なし）
- `src/app/list/page.tsx` — リスト表示のチェックボックス（変更なし）

- `npm run build` … `✓ Compiled successfully`
- 挙動のトレース（コード上）:
  - 既存・未完了 → 「完了にする」→ `patch` → `onSave`/`save` で保存 →
    本文が完了表示に切り替わり、フッターが「閉じる」1つになる
  - 習慣ゴースト枠 → 「完了にする」→ `materializeHabitBox` で実体化 →
    `setHabitLog` で習慣も記録 → `box.id` が変わり再初期化されるが完了表示で整合
  - 新規予定のフッターは変更なし
- **ブラウザ実機確認は未実施**（このセッションは無人扱いで dev サーバを起動できなかった）。
  スマホで「過ぎた予定をタップ →『完了にする』→ 完了表示になる／別端末にも反映」を
  確認してほしい。

## 残件

- `NowBar` の「直前の予定」は 60分窓のまま。これは仕様どおりで今回は触っていない。
- 予定シートの完了に対する自動テストは無い（このリポジトリは純関数テストのみで、
  コンポーネント描画テストの基盤が無い）。`lastAdviceFor` のように
  完了導線の判定を純関数へ切り出すなら別途。
