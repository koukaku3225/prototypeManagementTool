# 「成長する木」のUIデザイン案

日付：2026-09-13
種別：設計（デザインモックアップ）
状態：案を提示、実装はまだ

## 結論

目標の階層を1本の木として見せるスマホ画面のモックアップを作った。アプリ本体のコードはまだ変えていない。

- モックアップ: https://claude.ai/code/artifact/25e8c0b0-4792-4cac-9aab-f825aab64833

## 依頼と背景

竜一さんから「今のUIが好きでない。グラフィカルにしたい。全体のゴールとサブゴールが分かるメタファーはないか」という相談があった。今の `/big-story` 画面は、理想像・大事にしているもの・節目・目標が同じ見た目のダークカードを縦に並べているだけで、階層が見出しの文字でしか伝わらない。

## 変更内容

データの階層を、木の部位にそのまま割り当てた。

| 木 | 今のデータ | 見せ方 |
|---|---|---|
| 光（木が伸びていく先） | `BigStory` の理想像 | 画面上部の一文と、空の明るい部分 |
| 根 | `BigStory.values` | 地面の下に4本。枝を選ぶと、その目標につながる根が光る |
| 地面 | 今の立ち位置 | 地表の線 |
| 幹 | 大きな物語 | 1本 |
| 枝 | `GoalCard` | 枝の先にラベル。タップすると下のパネルに中身が出る |
| 小枝 | `Checkpoint`（週・月） | 枝から分かれる細い線 |
| 葉・芽 | `Habit` | 続いていれば葉、まだなら芽 |

状態は5種類の形で見せる：芽（まだ）・葉（続いている）・花（中間目標を完了）・実（目標を達成）・落ち葉（今回は終わりにした）。「今回は終わりにする」を落ち葉として土に返す見せ方にしたのは、中間目標の設計で決めた「失敗扱いしない」という方針に合わせるため。

## 仕組みの説明

- 木はSVG1枚。枝ごとにグループにしてあり、タップ（またはキーボードのEnter）で選択が切り替わる
- 選択していない枝は薄くなり、選んだ枝とその根だけが目立つ
- 下のパネルに、選んだ目標の中間目標（期間の進み具合バー付き）と習慣の一覧が出る
- ライト・ダーク両方の配色を用意した

## 追記：育ち方のシミュレーター

竜一さんから「育つとどう見えるか」「他の表示にするとどうなるか」「木をもっとリアルに」「価値観と目標の紐付けはどうするのか」「進むと枝が生えるのか」を試したいと依頼があり、シミュレーターを作った。

- シミュレーター: https://claude.ai/code/artifact/835aad3e-f898-4203-ada2-3b54d47c844b
- 画面下に横スワイプできるスライダー（経過週数・目標の数・中間目標を足す間隔・習慣の継続率・完了率・「今回は終わり」の率・評価した割合）と、状況の例（始めたばかり／習慣が途切れた／1年後など）のボタン
- 表示は3種類：1本の木（全体）／森（目標ごとに1本、地下で価値観がつながる）／枝のアップ（中間目標の名前つき）
- 木は座標の手描きをやめ、太さが先へ行くほど細くなる枝と、色にばらつきのある葉をプログラムで生成するようにした
- 育ち方の決め事：枝が生えるのは「足したとき」だけで、進み具合では伸ばさない。進み具合は芽→花→実で見せる。進み具合で伸ばすと、手が止まった週に木が枯れたように見え、責める見た目になるため
- 価値観のつなぎ方は2案を切り替えられる：目標ごとに自分で選ぶ／中間目標の評価（今ある `linkedValues`）から集計する

## 残っていること

- 竜一さんに見てもらい、この方向でよいかを決めてもらう
- 実装する場合の論点
  - 枝が5本、10本と増えたときの配置（今は手で座標を決めた3本だけ）。自動で枝を並べる仕組みが必要
  - 文字の長い目標をラベルにどう縮めるか（短い呼び名の欄を足すか）
  - 今の `/goals` 一覧・`/goal/[id]` 詳細画面との役割分担
