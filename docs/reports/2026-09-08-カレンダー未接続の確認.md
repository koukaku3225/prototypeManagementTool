# Googleカレンダーとの同期が見えない件の確認

日付：2026-09-08
種別：調査（コード変更なし）
状態：完了（原因確定。対応には本人の操作が必要）

## 結論

**そもそも本番で連携が有効になっていない。** だから同期して見えるわけがない、が正しい。

本番の設定画面で「Googleカレンダーと連携する」を押すと、次のメッセージが出た。

```
この環境ではGoogleカレンダー連携の鍵（GOOGLE_OAUTH_CLIENT_ID / _SECRET）が
設定されていません。Vercelの環境変数に追加して、再デプロイしてください。
```

つまり連携が「一度も成立していない」のではなく、**連携する手前で止まっている**。
これは[9/7の報告](2026-09-07-カレンダーの重ね表示.md)の「残っていること」に書いた
未対応タスクがそのまま残っている状態。

## 依頼と背景

「Googleカレンダーとタイムボクシングが同期していないように見える」という指摘を受け、
次の4点を実際に動かして確認するよう依頼された。

1. Googleカレンダーを操作 → 時間割のUIに反映される
2. 時間割を操作 → Googleカレンダーに反映される（ほかの予定に影響しない）
3. Googleカレンダーで予定を消す → 紐づいた時間割の予定も消える（ほかは消えない）
4. 時間割の予定を消す → Googleカレンダーの予定も消える

## 確認したこと

| 確認 | 方法 | 結果 |
|---|---|---|
| 連携状態 | 本番にログインして設定画面を確認 | 「連携する」ボタンのみ。連携済みの表示なし |
| 連携できない理由 | `/api/calendar/connect` を実際に踏む | 鍵未設定のメッセージが表示され、Google側にすら遷移しない |

これで「同期していないように見える」の原因は完全に説明できる。
連携自体が成立していないので、依頼の1〜4はどれも試しようがない。

## コードを読んで分かったこと（未検証・ロジックの確認のみ）

鍵を入れて連携が成立すれば、依頼の1〜4は**「目標設定コーチ」という専用カレンダーに限り**
満たされるように書かれている（[`src/lib/calendar/engine.ts`](../../src/lib/calendar/engine.ts)）。

| 依頼 | 該当ロジック |
|---|---|
| 2. 時間割→カレンダー | `action === "createEvent" / "updateEvent"` |
| 1. カレンダー→時間割 | `action === "importBox" / "updateBox"` |
| 4. 時間割の削除→カレンダー | `action === "deleteEvent"`（時間割に無く、印つきの予定） |
| 3. カレンダーの削除→時間割 | `action === "deleteBox"`（`cancelled` 判定） |
| ほかの予定に影響しない | 判定は `link.calendarId`（専用カレンダー）に閉じている。ほかのカレンダーへは読み書きどちらも行かない |

**ただし2点、依頼の書き方とズレる可能性がある箇所がある。**

1. **依頼の「Googleカレンダー」が本人のメインカレンダーを指しているなら、上の同期は起きない。**
   9/7に選んでいただいたB案どおり、メインカレンダー（本人が普段使っているほう）は
   **読み取り専用の薄い重ね表示だけ**で、時間割との削除連動も書き込みも一切ない
   （[9/7の報告](2026-09-07-カレンダーの重ね表示.md)）。双方向・削除連動があるのは
   「目標設定コーチ」という**アプリが新しく作る専用カレンダー**の側だけ。
2. **同期は「時間割を開いた瞬間に1回」だけ走る**（[`CalendarSyncBoot.tsx`](../../src/components/CalendarSyncBoot.tsx)）。
   保存するたびに即座に飛ぶわけではないので、片方を変えたあとは
   **時間割の画面を開き直す（リロードする）まで反映されない**。

## 残っていること（本人の操作が必要）

私は秘密の値を入力できず、`vercel` CLIにもログインできないため代行できない。

1. **Vercelに環境変数を入れる**
   ```bash
   vercel login
   bash scripts/push-env-to-vercel.sh --apply
   ```
2. Google Cloudの「承認済みリダイレクトURI」に
   `https://prototype-management-tool.vercel.app/api/calendar/callback` を追加
3. OAuth同意画面のスコープに `calendar.readonly` を追加（テスト中アプリなので再同意が要る）
4. 本番の設定画面から「Googleカレンダーと連携する」を押し、**Google側の同意画面はご本人が
   ログイン・許可する**（この画面の操作は代行できない）

これが済めば、私の手元にあるGoogleカレンダー連携（別の接続）で実際のカレンダーの中身を見ながら、
依頼の1〜4を実機で確認できる。連携が成立していない今は確認する対象そのものが無い。
