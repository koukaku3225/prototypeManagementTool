# 作成日の表示・書き出しファイル名がUTCで前日になる不具合を直す

日付：2026-09-19
種別：修正
状態：完了

## 結論

目標の書き出し（Markdown/JSON）と対話ログの書き出しに出る「作成日」・ファイル名の日付が、
JST 朝9時までに作った目標や対話では**前日の日付**になっていたのを直した。
`toLocalDate(new Date(...))` を通すようにしたことで、常にJSTの暦日になる。

## 依頼と背景

定期タスクの棚卸しの一環で、`AGENTS.md` の「日付」節が名指しで禁止しているパターン
（`new Date().toISOString().slice(0, 10)` を使うと、UTC変換によりJST朝9時までは前日になる）
が実際にまだ残っていないかを調査した。過去の棚卸し（9/9〜9/19）では `src/lib/date.ts` の
ヘルパーへの置き換えが繰り返し行われてきたが、書き出し（export）まわりは対象になっていなかった。

## 変更内容・調査結果

`card.createdAt` / `session.startedAt` は `new Date().toISOString()` で保存したUTCの日時文字列。
これを `.slice(0, 10)` で切っている箇所が4つ残っていた。

- `src/lib/export.ts`：Markdown書き出しの「作成日: …」行
- `src/app/goal/[id]/page.tsx`：目標のMarkdown/JSON書き出しのファイル名（`goal-YYYY-MM-DD.md/.json`）
- `src/app/history/[id]/page.tsx`：対話ログのMarkdown書き出しのファイル名（`chat-YYYY-MM-DD.md`）

例：UTC `2026-08-25T16:30:00.000Z`（JSTでは `2026-08-26 01:30`）に作った目標を書き出すと、
これまでは「作成日: 2026-08-25」・ファイル名 `goal-2026-08-25.md` になっていた。
本人がJSTの深夜〜早朝に目標を作ると、書き出した資料に前日の日付が付く。

いずれも `src/lib/date.ts` の `toLocalDate(new Date(文字列))` に置き換えた。
画面上の日時表示（`new Date(...).toLocaleString("ja-JP")`）はブラウザのローカルタイムゾーンで
評価されるため、この不具合の対象外（history ページの一覧表示は元々問題なし）。

## 仕組みの説明

保存時は `new Date().toISOString()` でUTCの日時文字列にしている。そこから「日付だけ」を
取り出すとき、文字列の先頭10文字（`.slice(0, 10)`）を取るとUTCの日付になる。日本は
UTC+9なので、UTCの日付が変わる瞬間（UTC 15:00）はJSTでは深夜0時。つまりJSTで
午前0時〜8時59分に作ったものは、UTCではまだ前日のため、`.slice(0, 10)` だと前日の
日付が出てしまう。`new Date(文字列)` でいったんDateオブジェクトに戻し、
`toLocalDate()`（`getFullYear`/`getMonth`/`getDate` を使う＝実行環境のローカルタイムゾーンで
計算する）を通せば、サーバー・ブラウザともにJSTで動いている前提のこのアプリでは
正しい暦日になる。

  （テストは修正後のコードに対して実行し、2件とも成功）。

  確認した。
