# 作業後にMarkdown解説を残すスキルの追加

日付：2026-09-06
種別：設定変更
状態：完了

## 結論

このリポジトリで実装・修正・調査を依頼されたとき、作業後に日本語のMarkdown解説を残す `task-report` スキルを追加した。最終回答には保存した文書のリンクを載せる。

## 依頼と背景

MCP連携の設計書のように、仕組みや理由まで分かる説明を今後の作業にも残したい、という依頼に対応した。単なる変更一覧ではなく、会話を読んでいなくても結果を理解できる文書を目指す。

## 変更内容

- スキルに、適用条件・保存先・必須構成・検証の書き方を定義した。
- `AGENTS.md` に、対象依頼の開始時にスキルを読み、最終回答前に報告を保存するルールを追加した。
- 小さな修正、コード変更のない調査、原因未確定の調査も対象にした。
- 同名の別件は連番で保存し、既存文書の上書きを防ぐ。同一依頼の継続は既存報告を更新する。
- 設計書などのMarkdown自体が依頼された場合は、その文書に必要情報を含めて兼用できるようにした。

## 仕組みの説明

ユーザーが作業を依頼すると、エージェントがリポジトリのルールからスキルを読み、実作業と必要な確認を進める。終了時に、結論・背景・結果・仕組み・関連ファイル・検証・残件を `docs/reports/YYYY-MM-DD-短い内容.md` に保存する。

これはエージェントへの作業指示であり、ファイル保存を監視する常駐プログラムではない。依頼ごとに適用し、各編集操作のたびには生成しない。ユーザーが明示的に文書不要とした場合はその指示を優先する。

## 関連ファイル

- [task-report/SKILL.md](../../.agents/skills/task-report/SKILL.md)：報告を作る手順と構成。
- [AGENTS.md](../../AGENTS.md)：毎回スキルを参照するための入口。

## 確認したこと

スキルなしの独立したエージェントでは、修正や調査の4ケースがチャットの最終報告のみとなり、追加Markdownを作らないことを確認した。

スキルを読み込ませた独立したエージェントで、以下の5ケースを確認した。

| ケース | 確認結果 |
| --- | --- |
| ボタン文言だけの修正 | 短いMarkdown報告を作る判断 |
| 原因未確定・コード変更なしの調査 | 事実・仮説・次の確認を分けた報告を作る判断 |
| 環境不足で一部テスト未実施 | 未実施と理由を明記する判断 |
| 同日に同名の別件 | 別名で保存し上書きしない判断 |
| 設計書Markdownそのものを作成 | 依頼された文書を報告として兼用する判断 |

スキルファイルとAGENTSの追記を読み返した。今回のファイル作成を最初の適用例とした。アプリの実行コードは変更しておらず、アプリのテストは実行していない。

## 残っていること

設定はこのリポジトリ内に適用される。全プロジェクト共通の個人スキルとしては登録していない。将来の新しいタスクでの自動適用は、今回のシナリオ確認とは別に実運用で確認する。
