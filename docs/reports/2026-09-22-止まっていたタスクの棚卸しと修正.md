## 変更内容・調査結果

### 直した不具合：過去の日を「N日遅れ」と呼んでいた

**症状（手元のブラウザで確認）**

| 場所 | 修正前 | 修正後 |
|---|---|---|
| 時間割の日付ボタン（昨日） | `1日遅れ` / 2026-09-21 | `昨日` / 2026-09-21 |
| 時間割の日付ボタン（3日前） | `3日遅れ` / 2026-09-19 | `3日前` / 2026-09-19 |
| 時間割の日付ボタン（5日後） | `2026-09-27` / 2026-09-27 | `5日後` / 2026-09-27 |
| ヒートマップのマスの説明 | `9日遅れ できた` | `9日前 できた` |

**原因**

どちらも `dueLabel()` を使っていた。これは**期限**のための言い回しで、
「過ぎた日＝遅れ」「先の日＝日付そのもの」を前提にしている。
時間割の日付見出しもヒートマップのマスも、期限ではなく**ただの日付**なので、
語彙が合っていなかった。先の日がそのまま返るので、日付が2段に並ぶ副作用もあった。

**直し方**

`src/lib/date.ts` に `dayLabel(date, base?)` を足した。
今日／明日／あさって／昨日／おととい／N日後／N日前を返す。
期限の残りは従来どおり `deadlineCountdown()`（「あと12日」「3日過ぎ」）が受け持つ。
`dueLabel` は呼び出し元がこの2箇所だけだったので消した。

### 確かめて閉じたもの

- **わたし画面のヒートマップ（9/21 の「未確認」）**。
  週N回の習慣（週3回）のマスは、記録のない日が `予定なし`（薄い枠）になり、
  読み上げも「直近35日のうち、17日できています」と、予定日数を言わない形だった。
  毎日の習慣のほうは「直近35日のうち、予定35日に対して10日できています」で、
  こちらは今までどおり。9/21 の修正が意図どおり効いている。
- **画面どうしの数の食い違い**。予定を1件足し、中間目標に紐づけ、完了まで通して
  時間割・今日・目標の一覧・森・中間目標タブ・目標の詳細の6画面を見た。
  合計時間（今週3時間）・件数（今日の予定 1/2）・中間目標（1.5 → 2 / 10時間）・
  「次の予定」まで、すべて同じ数になっていた。
- **Google で消された予定**。目標の詳細の「過去・完了も含めて全3件」にも
  `Googleで削除済み` と出ており、時間の合計にも件数にも入っていない。
- **はじめての状態（データが空）**。時間割・今日・中間目標・わたしの4画面とも、
  空のときの案内と次の一歩が出る。落ちる画面は無かった。
- **書き出し**。設定画面の「下の欄に出す」で、目標・大きな物語が JSON で出ることを確認。

## 仕組みの説明

時間割の日付ボタンは、上段に「その日が今日から見てどこか」、下段に実際の日付を出す。
上段の言葉を作っているのが `dayLabel()` で、今日からの日数の差だけで決まる。
差が 0 なら「今日」、-1 なら「昨日」、-9 なら「9日前」。
ヒートマップは同じ関数を使って、マスにカーソルを合わせたときの説明
（「9日前 できた」）を作る。

期限（目標の「いつまでに」）は別の関数 `deadlineCountdown()` が担当していて、
そちらは今までどおり「あと89日」「3日過ぎ」と出る。
**「遅れ」と言ってよいのは期限だけ**、という切り分けになった。
