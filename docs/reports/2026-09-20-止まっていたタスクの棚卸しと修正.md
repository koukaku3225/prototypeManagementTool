## 直したこと

### 1. 今日の画面の件数が、時間割の件数と食い違っていた

**症状**：Googleカレンダーで消された予定が1件ある日に、
時間割は「予定 1時間30分 ・ 2件」、今日の画面は「今日の予定 0/3」と出ていた。

9/19 に「Googleで消された予定は時間の合計から外す」（`countsAsPlanned`）を入れたとき、
時間割の件数（`plan/page.tsx`）はそろえたが、今日の画面の分母だけ
`boxes.length`（全部）のままだった。時間は外れているのに件数は入っている、
という中途半端な状態だった。

**直し方**：今日の画面の分母も `countsAsPlanned` を通す。

### 2. Googleで消された予定が、今日の画面と目標の詳細では普通の予定に見えていた

**症状**：時間割では薄く描いて「まとめて片付ける」を勧めているのに、
今日の画面と目標の詳細では、消された予定が他の予定とまったく同じ見た目で並んでいた。
今日の画面にはチェックボックスまで付いていて、**消えた予定をそのまま「完了」にできた**。

**直し方**：どちらの画面にも「Googleで削除済み」と赤系の小さい文字で出す。
時間割と同じ事実を、同じ場所で伝えるようにした。消すかどうかは今までどおり本人が決める。

### 3. 目標の一覧が、期間の終わった中間目標を「今週 … 残り0日」と出し続けていた

**症状**：先週の中間目標を閉じ忘れていると、目標の一覧（`/goals`）と森（`/tree`）の
目標カードに、その**先週のものが「今週 …… 残り0日」として居座り**、
今週の中間目標がいつまでも出てこなかった。

**原因**：`nearestActive()` が「活動中のうち期限がいちばん近いもの」を返していて、
期限が過ぎているかどうかを見ていなかった。引数で `now`（今日）を受け取っているのに、
関数の中で一度も使っていなかった。

**直し方**：まだ期間が残っているものを先に見る。残っているものが1件も無ければ、
いちばん最近終わったものを返し、表示は「今週」ではなく「中間目標 … 期間が終わりました」にする。
今日の画面（`/list`）は前から正しく「期間が終わりました／振り返る →」と出していたので、言い方をそろえた。

### 4. 一度も続いていない習慣に「保険を使用中」と出ていた

**症状**：まだ一度もできていない習慣で、わたし画面に「0日連続 ・ 保険を使用中」と出ていた。

保険（フリーズ）は「続いているものを1回だけ守る」仕組みなので、
連続が0日なら守るものが無い。連続を数える処理が、途切れを見つけた時点で
保険を消費したことにしていたため、結果が0日でも「使用中」になっていた。

**直し方**：連続が0日なら保険は使っていないことにする（`computeStreak`）。
わたし画面の表示条件ではなく数え方の側を直したので、
`freezeLeft`（保険の残り）を使う画面が増えても同じ結果になる。

## 仕組みの説明

4件とも「同じ1つの事実を、複数の画面がそれぞれ別々に数え直していた」ことが原因。

```
TimeBox（予定1件）
 ├ sourceGoneAt が入っている＝Google側では消えた
 │   ├ 時間割         … 薄く描く・合計から外す・件数から外す   ← 9/19に直した
 │   ├ 今日の画面     … 印なし・合計からは外す・件数には入れる ← ここが食い違い（今回1・2）
 │   └ 目標の詳細     … 印なし                                 ← 今回2
 │
Checkpoint（中間目標1件）
 └ period.end < 今日＝期間が終わっている
     ├ 今日の画面     … 「期間が終わりました／振り返る →」     ← 前から正しい
     └ 目標の一覧・森 … 「今週 … 残り0日」                     ← 今回3
```

「どう見せるか」を画面ごとに書いていたのが食い違いの元なので、
判断そのもの（`countsAsPlanned` / `isPeriodOver` / `nearestActive`）を共通の関数に寄せ、
画面はその結果を出すだけにした。
