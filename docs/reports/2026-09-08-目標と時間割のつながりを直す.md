## 選んだ改善3件

### 改善1（最優先）: 予定の目標プルダウンが、実データと食い違う（★5）

**誰が、どの場面で困るか**
目標を「完了」にした人が、その目標に紐づく予定を開いたとき。

**根拠**
`TimeBoxSheet` / `RunningBar` は進行中の目標だけを `<option>` にしていた。
`<select value={draft.cardId}>` に対応する `<option>` が無いと、ブラウザは
先頭（＝「（紐づけない）」）を選択状態として描く。
実データの `cardId` は紐づいたままなので、画面が嘘をつく。
選択肢に出てこないので、紐づけ直すことも外すこともできない。

呼び出し側も絞り込んでいた（`src/app/plan/page.tsx` の
`all.filter(c => c.status !== "done")`、`src/app/list/page.tsx` の `cards={active}`）。

**やったこと**
純粋関数 `goalSelectOptions(cards, currentId)` を追加した。

- 並べるのは進行中の目標
- ただし**いま紐づいている目標だけは、完了していても必ず残す**（「◯◯（完了）」）
- 一覧に無いidなら「（削除された目標）」として残す

呼び出し側は絞り込みをやめ、全件を渡すようにした。何を並べるかは1箇所で決まる。

---

### 改善2: 目標から時間割へ来ても、目標が引き継がれない（★6）

**誰が、どの場面で困るか**
目標画面の「時間割で予定を作る →」を押した人。全員。

**根拠**
リンク先が素の `/plan` で、目標のidを渡していなかった
（`src/app/goal/[id]/page.tsx`）。`/plan` 側にも受け取る口が無い。
その目標のために時間を取りに来たのに、予定を作るとプルダウンから選び直しになる。

**やったこと**
`/plan?card=<id>` にして、`/plan` が受け取るようにした。
判定は純粋関数 `presetCardIdFrom(search, cards)` に切り出してある。
実在しないid・完了済みの目標は無視する（URLは書き換えられるし、
目標を完了にしたあとに古いリンクを踏むこともある）。

`useSearchParams` ではなく `location.search` を読んでいる。
この画面はクライアント側だけで完結していて、Suspense 境界を足す理由がない。
`CalendarLink` が `?calendar=` を読むのと同じやり方に揃えた。

### 改善3: 今日のリストが時刻順に並ばない（★2）

**誰が、どの場面で困るか**
リスト表示（`/list`）を使う人。21:00 の習慣が 23:00 の予定の下に出る。

**根拠**
`[...timeBoxesOn(today()), ...habitBoxesOn(...)]` と**足しているだけ**だった。
`timeBoxesOn()` は開始時刻で整列するが、そのうしろに習慣の枠を継ぎ足すので、
「実体の枠 → 習慣の枠」が常にこの順になる。
時間割（`DayGrid`）は時刻で位置が決まるので影響が出ず、リスト表示にだけ現れる。

**やったこと**
純粋関数 `sortByStart()` を `src/lib/timebox.ts` に追加し、合わせたあとに並べ直す。
時刻が壊れている枠は消さずに末尾へ落とす。同時刻は終了が早いほうを先にして、
並びが毎回同じになるようにした。

## 仕組みの説明

### 目標プルダウンが何を並べるか

```
cards（全件） ──┐
                ├─→ goalSelectOptions(cards, いま紐づいているid)
いまのcardId ───┘        │
                         ├─ 進行中の目標をぜんぶ
                         └─ いま紐づいている目標が上に無ければ、必ず足す
                              ├─ 目標が見つかる    → 「◯◯（完了）」
                              └─ 目標が見つからない → 「（削除された目標）」
```

これで「画面で見えている紐づけ先」と「保存されている `cardId`」が必ず一致する。
外したい人は「（紐づけない）」を選べばよい。

### 目標から時間割への引き継ぎ

1. 目標画面の「時間割で予定を作る →」が `/plan?card=<目標のid>` へ飛ぶ
2. `/plan` は開いたときに `presetCardIdFrom(location.search, 目標一覧)` を呼ぶ
3. 実在して、かつ進行中ならそのidを覚える（そうでなければ無視）
4. その画面で作る新しい予定は、最初からその目標に紐づいている

シートには選択済みとして見えるので、違えばその場で変えられる。
