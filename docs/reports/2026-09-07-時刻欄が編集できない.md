# 予定シートの時刻欄が編集できない件

日付：2026-09-07
種別：修正
状態：完了（純粋関数はテストで確認済み。実機ブラウザでの確認は未実施）

## 結論

時刻欄（`<input type="time">`）が**入力を無言で書き換えていた**。原因は1つではなく3つ重なっていた。

1. **`24:00` を value に渡していた。** HTMLの仕様では時は00〜23までで、それ以外はブラウザが
   無効値として**空文字に落とす**。欄が空になり、タップすると `0:00` から始まる。
   送っていただいた2枚目のスクリーンショットは、この状態である。
2. **欄が空になると開始が `00:00` へ飛んでいた。** Androidの時刻ダイアログには「削除」があり、
   押すと value が空文字になる。それを `?? 0` で拾っていた。
3. **終了を開始以前にすると、無言で元の値に戻していた。** 画面が何も変わらないので、
   本人には「編集できない」としか見えない。

「終わり側が反映されない」は 3 が、「0:00 のダイアログが出る」は 1 と 2 が説明する。

修正済み。`npm test`（24スイート全通過）・`npx tsc --noEmit`・`npm run build` すべて成功。

## 依頼と背景

> この時間の編集ができないです。特に終わり側の処理が。これで反映されない。

スクリーンショット2枚：

- 20:04 — 予定シート。`22:30 〜 22:45`「リラックス」
- 20:05 — 時刻ダイアログが `0:00` で開いている（分の文字盤、削除／キャンセル／設定）

## 調査結果

### この不具合はいつからか

`git log -S` で確認したところ、時刻欄も `normalizeRange` も
**機能追加時（`b64791f`）から一度も変わっていない**。昨日のUI変更で入ったものではなく、
タイムボクシングを作ったときから入っていた。

### 何が起きていたか（実際に動かして確認）

`normalizeRange` は純粋関数なので、そのまま Node で叩いて確かめた。

```
--- 終わりを『後ろ』へ動かす ---
  入力: start="22:30" end="23:00"  → 出力: start="22:30" end="23:00"   そのまま

--- 終わりを『前』へ動かす ---
  入力: start="22:30" end="22:30"  → 出力: start="22:30" end="22:45"   ★戻される
  入力: start="22:30" end="22:15"  → 出力: start="22:30" end="22:45"   ★戻される
  入力: start="22:30" end="21:00"  → 出力: start="22:30" end="22:45"   ★戻される

--- 時刻欄を空にした（ダイアログの「削除」） ---
  入力: start="22:30" end=""       → 出力: start="22:30" end="23:00"   ★勝手に伸びる
  入力: start=""      end="22:45"  → 出力: start="00:00" end="22:45"   ★00:00 へ飛ぶ

--- 開始を後ろへ動かす ---
  入力: start="23:00" end="22:45"  → 出力: start="23:00" end="23:15"   ★長さが潰れる
```

原因は `normalizeRange` の2行。

```ts
const s = toMinutes(start) ?? 0;              // ← 空欄が 0（＝00:00）になる
let e = toMinutes(end) ?? s + DEFAULT_DURATION;
if (e <= s) e = Math.min(DAY_MINUTES, s + SNAP_MINUTES);  // ← 入力を捨てて押し戻す
```

この関数自体は間違っていない。**「保存されている壊れた値を直す」ための関数**であって、
「人がいま打っている途中の値」に当てるものではなかった。それを onChange のたびに
通していたことが、本当の原因である。

### `24:00` が欄を空にする経路

`toTime(1440)` は `"24:00"` を作る。これは正規の値として、次の3つの経路で普通に生まれる。

- 一日の最後のマス（23:30–24:00）をタップ → `slotAt(1439)`
- 習慣から自動で並ぶ枠（`tests/habit-plan.test.mjs` が `end === "24:00"` を固定している）
- `normalizeRange` 自身の `Math.min(DAY_MINUTES, ...)`

そして WHATWG HTML の time state は「値が valid time string でなければ空文字にする」と
定めており、`24:00` は valid ではない（時は00〜23）。つまり **`24:00` に終わる枠を開くと、
終了欄は必ず空で表示され、タップすると `0:00` から始まる**。

しかもこの状態で「削除」を押すと `normalizeRange("23:30","")` → `end = "24:00"` となり、
また空欄に戻る。**直そうとしても直らないループ**になっていた。

### なぜドラッグは壊れていなかったか

ドラッグは `moveBox` / `resizeBox` を通る。これらは**両端をまとめて計算する**ので
`e <= s` が起きない。時刻欄だけが `normalizeRange` を通していた。

## 変更内容

判断は純粋関数に寄せ、画面側は「反映する」「断った理由を出す」だけにした。

### `src/lib/timebox.ts`（追加）

| 関数 | 役割 |
|---|---|
| `toTimeInputValue(time)` | 欄に渡す値。`24:00` は `23:59` に寄せる。読めない値は空文字（**00:00 と読み替えない**） |
| `applyStartInput(box, v)` | 開始を直したとき。**長さを保ったまま枠ごと動かす**（Googleカレンダーと同じ） |
| `applyEndInput(box, v)` | 終了を直したとき。長さだけ変える。開始以前なら**動かさず、理由を返す** |

3つとも「読めない入力（空欄・入力途中）のときは**何も変えない**」を守る。

### `src/components/TimeBoxSheet.tsx`

- `value` を `toTimeInputValue()` 経由にした（`24:00` で欄が空になるのを止める）
- `onChange` を `applyStartInput` / `applyEndInput` に差し替えた
- 値が変わったときだけ保存する（変わっていないのに `onSave` を呼ぶと、
  更新時刻だけ動いてカレンダー同期が無駄に走る）
- 断ったときは欄の下に「終わりは開始より後にしてください」と出す

### `tests/timebox.test.mjs`

18件追加（timebox は 63 → 81 件）。先にテストを書いて赤を確認してから実装した。

## 仕組みの説明

直したあとの動きは次のとおり。

| 操作 | 前 | 後 |
|---|---|---|
| 22:30〜22:45 の**開始**を 23:00 に | 23:00〜23:15（長さが潰れる） | 23:00〜23:15 |
| 09:00〜17:00 の**開始**を 10:00 に | 10:00〜10:15（**7時間45分が消える**） | 10:00〜18:00（長さを保つ） |
| **終了**を 23:30 に | 22:30〜23:30 | 22:30〜23:30 |
| **終了**を 22:00（開始より前）に | 何も起きない | 何も起きない＋理由を表示 |
| 欄を「削除」で空に | **開始が 00:00 へ飛ぶ** | 何も変わらない |
| 23:30〜24:00 の枠を開く | **終了欄が空。直せない** | 終了欄に 23:59 と出る |

「終了を開始より前にしたとき」だけは、機械的な正解が無いので判断した。
**枠ごと前へ動かす**案も考えたが、9:00〜17:00 の終了を誤って 8:00 にしただけで
枠が 0:00〜8:00 へ飛ぶことになり、取り返しがつかない。
**動かさず、理由を出す**ほうを選んだ。Googleカレンダーは終了の選択肢に開始より前を
出さないので、そもそもこの状態を作れない ―― ネイティブの時刻欄では真似できないため、
断る形にしてある。ここは好みが分かれるので、変えたければ言ってほしい。

**未検証**：実機ブラウザでの動作確認はしていない。このセッションは定期タスクとして
起動したため dev サーバーを立ち上げられなかった（承認する人がいない、という理由で
ハーネスに止められる）。純粋関数の挙動はテストで固定してあるが、
**Android Chrome の時刻ダイアログが実際にどう振る舞うかは見ていない**。

確認していただく手順：

1. 23:30〜24:00 の枠を作って開く → 終了欄に `23:59` が出ること（以前は空欄）
2. 22:30〜22:45 の枠で、終了を 22:00 にする → 欄の下に理由が出ること
3. 9:00〜17:00 の枠で、開始を 10:00 にする → 18:00 まで一緒に動くこと
4. 時刻ダイアログの「削除」を押す → **何も変わらない**こと（以前は 00:00 へ飛んだ）
