## 結論

基本の往復（作成・改名・削除・時刻変更・終日・24時・重ね表示）は仕様どおりに動いた。
ただし**「Google で作った予定（印なし）」を取り込んだ枠まわりに不具合が3件**あり、
うち1件は本番で実際に予定の重複を起こしている。

## 前提（仕様）

- 同期は**時間割（/plan）を開いたときに1回だけ**。保存しただけでは飛ばない
- 同期するのは専用カレンダー「目標設定コーチ」だけ。メインカレンダーは重ね表示（読み取りのみ）
- アプリが作った予定には印（`extendedProperties.private.timeboxId`）が付く。印の無い予定は「人がカレンダーで作ったもの」
- 両方にあって内容が違えば、新しいほう（`updatedAt` と `event.updated`）を採用。title/start/end をまるごと

## 不具合の詳細

### A. 取り込み枠の予定IDが落ちると、予定が二重になる（本番で発生）

**起きたこと**：11:37:13 に、今日の枠と検証枠のすべてから `google_event_id` が一斉に消えた
（Supabase の `updated_at` がすべて同じ時刻）。3秒後の同期で、Google で作った G1・G8 が
アプリ・Google の両方で2件ずつになった。

**仕組み**（`engine.ts` の `ownedEvent`）：
- 予定IDの無い枠は、印（timeboxId）で予定を探す
- アプリが作った予定は印があるので見つかる → 何も起きない（今日の枠が無事だったのはこれ）
- Google で作った予定には印が無いので見つからない → 「まだ無い」と判断して**新しい予定を作成**
- 元の予定は誰にも対応づかない → 「Google で新規作成された」と判断して**もう一度取り込み**

**IDを落とした犯人は未特定**。Supabase のログでは、同じ時刻に Windows の Chrome 153 から
本番サイト経由でトークン更新（11:37:00）→ 読み書きが出ている。この PC の Chrome の
`gc.lastCalendarId` は現在のカレンダーを正しく指しており、連携先も 01:22 から変わっていない。
ID を落とす処理は `applyCalendarReconnect`（繋ぎ直し検知）しか見当たらないので、
**別のウィンドウ／プロファイルなど、目印が古い画面が1回開かれた**可能性が高い。

### B. 取り込み枠をアプリで削除しても復活する

判断表 #4 は「印があれば消す、無ければ取り込む」。取り込み枠の元予定には印が無いので、
アプリで消すと「Google で新規作成された予定」と見なされ、毎回戻ってくる。
アプリから Google で作った予定を消す手段が無い。

### C. 書き込みがあって残した枠は、その後二度とカレンダーに戻らない

Google で予定を消すと、書き込みのある枠は `keepBox` で残るが、`googleEventId` は
消えた予定を指したまま。以後の同期は毎回「削除された → 書き込みがあるので残す」になり、
アプリで時刻を変えても予定は作り直されない。
