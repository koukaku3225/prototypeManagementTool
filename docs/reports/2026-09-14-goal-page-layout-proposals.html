長く見える原因

  • 毎日触る「予定・習慣・中間目標」が一番下。一度決めたら読み返さない「物語・理由」が上にいる。

各案の中身

おすすめ案A 並べ替え＋畳む（変更小・今の画面の延長）

  • 頻度順に並べ替え: なりたい姿 → 木 → 予定・習慣 → 中間目標 → つまずき → 目標の数値 → 背景（畳む）→ その他（畳む）。
  • 予定は「今日以降の未完了3件＋もっと見る」。過去・完了分は畳む。
  • 木は高さを抑え、凡例文は「？」アイコンに格納。
  • 保存（MD/JSON）・完了・削除は末尾の「その他の操作」に畳む。
  • 長所: データ構造もコンポーネントもそのまま。1ファイル中心の変更で済む。 短所: 1ページの縦長自体は残る（ただし見る範囲は上半分で完結）。

案B タブ（進める／計画／背景）

  • ページ上部に「なりたい姿」を固定し、下をタブで切替。タブ位置はURL（?tab=）で覚える。
  • 長所: 1画面の長さが3分の1程度になる。 短所: 別タブの内容が見えないので「つまずき」を忘れやすい。タブ操作が1回増える。

案C 木を目次にする（ツリー表示に統合）

  • 木の「根」を押すと大きな物語・理由、「小枝」で中間目標、「葉」で習慣をボトムシートで開く。
  • 長所: 木が飾りでなく操作の入口になり、面白さがある。 短所: GoalForest にタップ判定を足す必要があり実装が一番重い。キーボード操作・読み上げの配慮も要る。

案D 読むモード／編集モード

  • 普段は文章として詰めて表示（編集ボタン・入力枠なし、if-then は「もし○○ → △△」の1行）。編集時だけ今のUI。
  • 長所: 同じ情報量でも高さが大きく減る。案A・Bと組み合わせられる。 短所: 「すぐ直したい」ときに1手増える。EditableField の全箇所に表示切替が要る。

どの案にも足せる小さな改善

  • 上部にジャンプ用チップ（予定／習慣／つまずき／背景）を横並びで固定。
  • 「何を・どれくらい・いつまでに」を3行の見出しから1枚の要約に（期限は残り日数も表示）。
  • 空のブロックは「＋ 追加」の1行だけにする（「まだありません」＋ボタンで2行使っている）。
  • ブロック間の余白と内側 padding を少し詰める（16px→12px）。
