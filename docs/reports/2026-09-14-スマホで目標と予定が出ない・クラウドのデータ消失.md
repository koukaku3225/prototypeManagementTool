# スマホで目標が1つ・予定が出ない（クラウドのデータ消失）

日付：2026-09-14
種別：不具合調査・修正・データ復旧
状態：修正を本番反映（0b1f054）。PCで再現確認済み。スマホでの確認は本人待ち

## 結論

スマホを開いた瞬間に、**スマホの古い中身がクラウドへ「正」として送られ、PCで足した目標1件と予定14件がクラウドから消えていた**。
スマホはクラウドから取り込み直す経路も持っていなかったので、目標1つ・予定なしのまま表示されていた。

開いたときに「クラウドと端末を合体してから送る」形に直し、クラウドのデータもPCの中身と合体して元に戻した。

## 何が起きたか（実データで確認）

| 時刻（JST） | 出来事 | 根拠 |
|---|---|---|
| 15:41:23 | Android の Chrome から全キーの一括送信 | Supabase の edge_logs（UA: Android 10） |
| 15:41:27 | `goal_cards` から「月々5万円を稼ぐ力」を DELETE | 同上（`id=in.(f5d40667…)`） |
| 15:41:28 | `timeboxes` から予定を DELETE（今日の予定6件を含む14件） | 同上 |
| 以後 | 7〜15秒ごとに同じ一括送信を繰り返し | 同上 |

このとき、クラウドにはPCに無い予定13件（9/5〜9/19。スマホで作ったもの）も残っていた。
**どちらの端末で上書きしても、もう片方のデータが消える状態**だった。

## 原因

`decideSyncDirection` が「突合済み・端末とクラウドの両方に中身がある」ときに `push` を返し、
開くたびに `backfillAll`（この端末の中身を正として全部送る）を実行していた。
送信は「手元に無い行はクラウドから消す」（`reconcileCollection`）なので、
**しばらく開いていなかった端末を開くと、別の端末で足したものがクラウドから消える**。

## 修正

1. `decideSyncDirection`：突合済み・両方に中身あり → `merge`
2. `mergeWithReport`（`sync-decision.ts`）：目標・習慣・記録・予定・中間目標・対話の履歴を ID で合体
   - 片方にしか無いものは両方残す
   - 両方にあれば `updatedAt` が新しいほう、同じ・不明ならこの端末
   - この端末の並び・表現を保ち、クラウドから足した／置き換えたときだけ「変わった」とする
3. `resolveInitialSync`：合体した結果をこの端末に書いてから送る。変わったら1回だけ読み直す（30秒以内の2回目は見送る歯止め付き）

### 途中で起こした二次障害

最初の修正（7e658b5）は「変わったか」を文字列の比較で判定していた。並び順が違うだけで毎回「変わった」になり、
**PCで合体→送信→再読み込みが1秒ごとに繰り返された**（約5分。削除は0件、上書き保存のみ）。
タブを止め、判定を中身で行う形に直した（0b1f054）。

## データの復旧

- 修正前のクラウドを `backup` スキーマに退避（`backup.*_20260914_1600`）
- PC の localStorage を `zz.20260914-1550-before-restore.*` に退避
- 修正版でPCを開き、合体した結果をクラウドへ送った

## 残件

1. **スマホで開いて確認してもらう**（開き直すと合体され、目標2件と今日の予定が出るはず）
2. **削除の記録が無い**ので、別の端末で消したものが、それを持っている端末を開いたときに戻ることがある。
   スマホ由来の13件（「テスト」「さら」「いい」など、消したつもりのものかもしれない）がPCにも出るようになった。
   消しても戻る場合は、削除の記録（墓標）を持たせる対応が要る
3. `backup` スキーマの退避テーブルと `zz.*` の退避キーは、確認が済んだら消してよい
