## 変更内容・調査結果

### 1. 進行中の対話の無警告消失（データ消失防止）

**問題があった箇所**
- [src/app/goal/new/page.tsx](../../src/app/goal/new/page.tsx) の `startDialogue()`：`clearSession()` が進行中セッションの有無を確認せずに実行されていた
- [src/app/story/new/page.tsx](../../src/app/story/new/page.tsx) の `startDialogue()`：同上
- [src/app/history/[id]/page.tsx](../../src/app/history/%5Bid%5D/page.tsx) の `doResume()`：画面には「いま別の対話が進行中です。続きを始めると、そちらは記録に残したうえで置き換わります。」と表示するのに、実装は `resumeArchivedSession(id)` を呼ぶだけで、退避（`archiveSession`）を一度も呼んでいなかった。**文言と挙動が食い違っていた。**

`archiveSession()`（完了済み対話の退避）はすでにあったが、呼ばれるのは対話が完了したときだけ（`src/app/big/page.tsx:135`、`src/app/card/page.tsx:246`）で、未完了のまま別の対話に切り替えるケースはカバーされていなかった。

**変更内容**
[src/lib/storage.ts](../../src/lib/storage.ts) に `archiveIfAbandoned(session, excludeId?)` を追加した。「未完了かつ発言が1件以上ある対話」だけを退避し、`excludeId`（続きから話す対象そのもの）は対象外にする純粋関数。3箇所の呼び出しを、上書き・削除の直前にこの1行を呼ぶ形に統一した。

確認ダイアログの追加はしていない（挟むかどうかはUXの判断のため）。今回の変更は「消える前に `/history` から後から見つけられるようにする」という、挙動を変えない範囲の安全網。

### 2. 習慣枠のドラッグ移動→取り消しで幽霊レコードが残る（データ整合性）

**問題があった箇所**
[src/app/plan/page.tsx](../../src/app/plan/page.tsx) の `moveByDrag()`。習慣から自動配置しただけの枠（[src/lib/habit-plan.ts](../../src/lib/habit-plan.ts) の `isGhost()` が `id.startsWith("habit-")` で判定するghost）をドラッグで動かすと、`save()` が新しいUUIDで実体化して保存する。ここで取り消し（Undoスナックバー）を押すと、動かす前のghostオブジェクト（idが `habit-...` のまま）をそのまま `upsertTimeBox()` していた。

`upsertTimeBox()`（[src/lib/storage.ts:667](../../src/lib/storage.ts)）はidで一致を見るだけなので、`habit-` で始まるidを持つ**実体**が新規に保存される。`isGhost()` はid文字列だけで判定するため、この行は以後ずっとghost扱いのまま残り続け、[src/components/TimeBoxSheet.tsx:129,458](../../src/components/TimeBoxSheet.tsx) の `fromHabit` 判定で削除ボタンが出ず、Googleカレンダー同期（`isGhostId`）からも除外される。ドラッグして動かした枠と、元の位置に復元された幽霊枠が両方残り、後者は二度と消せない。

**変更内容**
`moveByDrag` の取り消し処理で、動かす前が ghost だったかを判定し、ghost だった場合は `upsertTimeBox(before)` の代わりに、動かしてできた実体を `deleteTimeBox(real.id)` するようにした。実体を消せば `habitBoxesOn()` が habitId の重複を見て元のghost表示を自動的に復元する。

### 3. `/api/structure` に `signal: req.signal` が渡っていない（課金対策）

**問題があった箇所**
[AGENTS.md](../../AGENTS.md) は「上流（Anthropic）のストリームには `signal: req.signal` を渡し...忘れると、切断されたリクエストの生成が最後まで走って課金される」と明記しており、[src/app/api/chat/route.ts](../../src/app/api/chat/route.ts) は対応済みだった。しかし [src/app/api/structure/route.ts](../../src/app/api/structure/route.ts) の `client.messages.parse()` 呼び出し（big用・small用の2箇所）には `signal` を渡していなかった。`/big` は最大16000トークンを生成させる高コストな呼び出しで、ユーザーがタブを閉じても最後まで課金され続ける状態だった。

**変更内容**
両方の `client.messages.parse()` 呼び出しの第二引数に `{ signal: req.signal }` を追加した（`@anthropic-ai/sdk` の `parse(params, options?)` は `RequestOptions.signal` を受け付ける）。

## 仕組みの説明

- `archiveIfAbandoned`：セッションが「存在する」「置き換え対象自身ではない」「未完了」「発言が1件以上ある」の全てを満たすときだけ `gc.archive` に書く。これにより空のセッションや、続きから話している対象そのものを誤って複製しない。
- `moveByDrag` の修正：ドラッグ前が ghost なら「動かしてできた実体を消す」、実体だったなら従来どおり「元の状態に戻す」という2通りの取り消し方に分けた。
- `signal` 伝播：`req.signal` は Next.js の `Request` が持つ標準 `AbortSignal`。クライアント切断時に発火し、Anthropic SDK に渡すことで上流の生成も中断される。
