# 目標設定コーチと暴露療法トレーナーを、スマホアプリ（PWA）として入れられるようにした

日付：2026-09-24
種別：実装
状態：完了（ローカルの本番ビルドで確認し、本番へ反映。実機スマホでのインストールは本人確認待ち）

## 結論

2つのアプリ（目標設定コーチ・暴露療法トレーナー）を、スマホのホーム画面に**アプリとして入れられる**ようにした。
画面の中に「スマホアプリとして使う」の枠を置き、端末に合わせて入れ方を出し分ける。

| アプリ | ボタンの場所 | 本番URL |
|---|---|---|
| 目標設定コーチ | 下のタブ「わたし」→「そのほか」の一番上 | https://prototype-management-tool.vercel.app/me |
| 暴露療法トレーナー | 下のタブ「設定」の一番上 | https://exposure-trainer.vercel.app/settings |

アプリとして開いているときは、この枠は出ない。

## 依頼と背景

2つのアプリはWebアプリで、スマホではブラウザから開くしかなかった。PWA（ホーム画面に置けるWebアプリ）にして、画面のどこかに「ダウンロード」のボタンを置いてほしいという依頼。

## 変更内容

### 端末ごとの出し分け

| 端末 | 出るもの | 理由 |
|---|---|---|
| Android の Chrome など | 「アプリをインストール」ボタン → ブラウザのダイアログ | ブラウザがダイアログを渡してくれる（`beforeinstallprompt`） |
| iPhone / iPad | 共有 →「ホーム画面に追加」の手順（3ステップ） | ページからインストールを呼ぶ手段が無い。どのブラウザでも同じ |
| それ以外 | ブラウザのメニューから入れる案内 | ダイアログを呼べない |
| アプリとして開いている | 何も出さない | もう入っている |

判断は純粋関数 `installMode()`（`src/lib/pwa.ts`、exposure-app は `lib/pwa.ts`）に集めた。iPad は Safari が「Mac」を名乗るので、指で触れるかどうかで見分けている。

### iPhone の注意書き

iPhone では、**ホーム画面のアプリと Safari で保存場所が別**になる。入れただけでは記録が引き継がれないので、入れる前に必ず伝える。

- 目標設定コーチ：ログインしてクラウド同期するか、JSON で書き出して読み込む
- 暴露療法トレーナー：設定の「書き出す」→ アプリ側で「読み込む」（クラウドが無いため）

Android はブラウザとアプリで保存場所が共通なので、この問題は起きない。

### 追加したもの（両アプリ共通の形）

- **名札**（`manifest.ts`）：名前・アイコン・全画面表示・色
- **アイコン**（`public/`）：192px・512px・マスク用512px（丸や角丸に切られても中央が残る）・iPhone用180px。
  目標設定コーチは藍の地に的、暴露療法トレーナーはコーラルの地に階段と旗
- **サービスワーカー**（`public/sw.js`）：インストールの条件を満たすため＋電波が無いときに最後の画面を出すため
- **下準備**（`PwaBoot`）：全画面共通でインストールのダイアログを取り置き、本番でだけサービスワーカーを登録
- **ボタンの枠**（`InstallCard`）
- iPhone 用の設定（`appleWebApp`・`apple-touch-icon`）と、上端の色（`themeColor`）
- `sw.js` をキャッシュさせないヘッダ（古い版を握り続けないため）

目標設定コーチはさらに、CSP に `worker-src 'self'` と `manifest-src 'self'` を明示した。

## 仕組みの説明

### サービスワーカーが触るもの・触らないもの

サービスワーカーは、ブラウザとサーバーの間に立って通信を横取りできる。広く横取りすると事故になるので、絞ってある。

| 対象 | 扱い | 理由 |
|---|---|---|
| 画面（ページを開く） | まずネット、だめなら覚えておいた画面 | キャッシュを先に出すと、デプロイ後も古い画面が出続ける |
| `/_next/static/` | 覚えておいたものを先に | ファイル名に中身のハッシュが入っていて、中身が変わらない |
| `/api/`・`/auth/`・`/oauth/` | 触らない | 対話・同期・ログイン。古い応答を返すと壊れる |
| 別ドメイン（Supabase・Google・フォント） | 触らない | ブラウザに任せる |

データは localStorage にあるので、画面さえ出れば、電波が無くても記録を見たり書いたりできる。

### 開発中は動かさない

`npm run dev` でサービスワーカーが入ると、古いファイルを握って「直したのに変わらない」が起きる。登録は本番ビルドでだけ行う。

## 残っていること

- **実機での確認**：Android の Chrome で「アプリをインストール」を押す、iPhone の Safari で「ホーム画面に追加」する、の2つは実機でしか確かめられない。この環境の埋め込みブラウザはインストールのダイアログを出さない
- iPhone は Safari とアプリで保存場所が別。暴露療法トレーナーはクラウド同期が無いので、書き出し → 読み込みが要る
- 通知（Webプッシュ）はまだ入れていない。今回のサービスワーカーはその土台になる（[リマインダー設計の提案](2026-09-17-reminder-options.md) の段階3）
