# Googleのメインカレンダーを時間割に取り込む

日付：2026-09-14
種別：機能追加＋同期の作り直し
状態：本番反映済み（943c81b）。本番での操作確認は一部のみ（残件を参照）

## 結論

Google のメインカレンダー（さはり）の予定が、時間割の枠として入るようになった。
取り込んだ枠には、完了・事前準備・振り返り・目標の紐づけ・色を付けられる。
タイトルと時刻は Google が正で、アプリでは変えられない。アプリで消すと非表示になり、次の同期でも戻らない。

あわせて、専用カレンダー「目標設定コーチ」を「アプリ → Google」の一方向にした。
実機検証で見つけた不具合A（二重になる）・B（消しても復活する）の経路はこれで無くなった。

## 決めたこと（竜一の選択）

| 論点 | 決定 |
|---|---|
| 取り込み元 | 連携アカウントのメインカレンダーだけ。ほかは重ね表示のまま |
| アプリで触れるもの | 完了・事前準備・振り返り・削除（＋目標・色）。タイトルと時刻は不可 |
| アプリで削除 | 非表示にするだけ。Google の予定は残す |
| 専用カレンダー | アプリ → Google の一方向 |
| 持ち方 | 枠（TimeBox）に印を足す（案1） |

## 仕組み

- **取り込み**：`/api/calendar/primary` が -7日〜+60日の予定を読み、`calendar/primary.ts` の `mergePrimary` がアプリの枠と突き合わせる
  - 枠のIDは予定IDから決まった値（`primaryBoxId`）。別端末で同時に取り込んでも二重にならない
  - 消えた予定：書き込み・完了なし → 枠を消す／あり → `sourceGoneAt` を付けて残す（「Googleで削除済み」）
  - 一度に6件以上消えるときは消さずに印だけ付ける（別アカウントへの繋ぎ直しなどで全滅させない）
  - 終日・日をまたぐ・断った招待・勤務場所・誕生日は取り込まない
- **非表示**：`hiddenAt` を付けて行を残す。`loadTimeBoxes()` が最初から除くので、どの画面にも出ない。書き込み系は `loadAllTimeBoxes()` を使う
- **専用カレンダー**：`decide.ts` を作り直し。アプリに枠があれば作る／直す、無ければ印付きの予定を消す、印の無い予定には触らない
  - 予定IDが落ちた枠は印で見つけてIDを付け直す（作り直さない）
  - 空タイトル（「（未記入）」で送っている）の枠を毎回書き直していたのを直した
- **DB**：`timeboxes` に `source` / `source_event_id` / `hidden_at` / `source_gone_at` を追加（本番に適用済み。既存の行は `source='app'`）

## 残件

1. **本番での操作確認が途中**。Chrome のウィンドウが裏にあり、ブラウザがタイマーと通信を大きく絞ったため、
   2回目以降の同期の結果を待てなかった。次を画面を出した状態で確かめる必要がある
   - Google で予定を足す → 時間割を開き直すと枠が増える
   - 取り込んだ枠のシートでタイトル・時刻が変えられず、完了・事前準備・振り返りは保存される
   - アプリで消す → 開き直しても戻らない／Google の予定は残る
   - Google で時刻を変える → 枠が追う（書き込みは残る）
   - Google で消す → 書き込みなしは消える／ありは「Googleで削除済み」で残る
2. 今日の枠の予定ID（不具合Aで空になったもの）が付け直されたかは未確認（同じく同期の完了を待てなかった）
3. 検証用に作った【検証】の予定は、アプリ・Google の両方から片付け済み
