# 中期目標（Checkpoint）の建て方を評価する機能 — 詳細設計

日付：2026-09-13
種別：設計
状態：完了（設計のみ。実装はまだ）

## 結論

前回の知識収集（[2026-09-13-目標の建て方の評価知識の収集.md](./2026-09-13-目標の建て方の評価知識の収集.md)）を踏まえ、`Checkpoint`（週/月の中期目標）に**任意で開ける評価パネル**を追加する設計にする。3軸（内発的動機・価値観との一致・人との関わり）は1つの点数に合算せず、独立したセクションとして見せる。

評価は**Checkpointに埋め込む**（`TimeBox.review`と同じ考え方）。作成・編集の主導線には影響させず、既定は畳んだ状態にして「更新を専用の儀式にしない」という前回のUI原則を守る。

## 設計内容

### データモデル

`src/types/goal.ts` に `CheckpointEvaluation` を追加し、`Checkpoint.evaluation?: CheckpointEvaluation | null` として埋め込む。

```ts
/**
 * 中期目標の建て方の自己評価。
 *
 * 3軸（動機・価値観・人との関わり）は性質が違うので1つの点数に
 * 合算しない。合算すると「何が良くて何が悪いか」が分からなくなる
 * （2026-09-13 の知識収集を踏まえた判断）。
 *
 * TimeBox.review と同じく、Checkpoint自体に埋め込む。頻繁に書き換わる
 * ログではなく、その中期目標のライフサイクルに1つ紐づく自己評価のため。
 */
export interface CheckpointEvaluation {
  /** セルフコンコーダンスの4動機。各1〜10、未入力は5（中立）から始める */
  motives: {
    identified: number;   // 同一化動機:本当に重要だと信じているか
    intrinsic: number;    // 内的動機:活動自体が楽しいか
    introjected: number;  // 取入的動機:義務感・不安回避・優越感からではないか
    external: number;     // 外的動機:外部からの強制・報酬によるものではないか
  };
  /** 大きな物語の価値観のうち、この目標が効くと感じるもの */
  linkedValues: string[];
  /** なぜそれが大事か。「何のため」を一言で */
  whyItMatters: string;
  /** 一緒にやる人・報告する相手がいるか */
  hasBuddy: boolean;
  buddyNote: string;
  updatedAt: string;
}
```

`motives`を4つとも5（中立）で初期化するので、SCSは常に計算可能（未評価時は0）。

### 計算（純粋関数）

`src/lib/checkpoint.ts` に追加。

```ts
/** セルフコンコーダンススコア。プラスが多いほど自己一致度が高い目標 */
export function selfConcordanceScore(m: CheckpointEvaluation["motives"]): number {
  return (m.identified + m.intrinsic) - (m.introjected + m.external);
}

/** スコアの言い方。責めない文言にする（達成率を追い詰めない、という既存方針） */
export function scoreLabel(score: number): { text: string; tone: "good" | "neutral" | "warn" } {
  if (score >= 6) return { text: "自分の内側から来ている目標", tone: "good" };
  if (score <= -6) return { text: "外側の理由が強めの目標", tone: "warn" };
  return { text: "半々くらいの目標", tone: "neutral" };
}
```

`tests/checkpoint.test.mjs` に、この2関数のテストを追加する（境界値 ±6 も含む）。

### UI

`CheckpointEditor.tsx` の各Checkpoint行に、既存の「編集」ボタン群の下へ `<details>` を1つ足す（`TimeBoxSheet.tsx`の「始める前に決めておく」と同じ折りたたみパターン）。

```
[週] [月]              2026-09-07 〜 2026-09-13
見込み客に3件連絡する                    [編集]
━━━━━━━━━━━━━━━━━━━━━━━━━━━ 残り3日

▸ たて方を評価する（任意）          ← 既定は畳む。評価済みなら要約を1行出す
```

開くと3ブロック。

**① 動機（セルフコンコーダンス）**
4つのスライダー（`<input type="range" min="1" max="10">`）。文言はDaiGoの元の質問文をそのまま使わず、4分類（同一化・内的・取入的・外的）という**構造だけ**を借りて、こちらで書き下ろす。

| 動機 | ラベル | 補足文 |
|---|---|---|
| 同一化 | 自分で選んだと言える | 昔は誰かに勧められたことでも、いまは自分の意思で続けている |
| 内的 | やっている最中が楽しい | 結果より、取り組んでいる時間そのものに惹かれている |
| 取入的（逆に高いほど注意） | やらないと落ち着かない | 後ろめたさや、人と比べた焦りが動かしている面がある |
| 外的（逆に高いほど注意） | 誰かの目や見返りが理由 | 評価・報酬・指示が無ければ、たぶん手をつけない |

動かすたびにスコアをリアルタイム表示：`いまのスコア: +6　自分の内側から来ている目標`

スコアがマイナスのときだけ、責めない一言を添える（考え方自体はDaiGoの動画にもある一般的なリフレーミングだが、文言は書き下ろし）。

> この目標をやめる必要はありません。続ける中で自分が得られるもの（新しいスキル・人との繋がり・将来の選択肢）を書き足してみると、感じ方が変わることがあります。

**② 価値観との一致**
`loadBigStory()`から`values`（例:「健康な肉体と精神」）をチップで並べ、複数選択可（`GoalCard`の`bigStoryId`と同じ発想で、無ければ「大きな物語がまだありません」と出す）。
その下に一言欄「なぜそれが大事か」（`EditableField`、単行）。

**③ 人との関わり**
Yes/Noの2択ボタン＋Yesのときだけ「誰と／どう報告するか」の一言欄。

### 保存タイミング

`TimeBoxSheet`のできばえチップと同じく、**触った瞬間に保存**する（動機スライダー・価値観チップ・Yes/Noは全て即時`patch()`）。専用の「保存」ボタンは置かない。一言欄（whyItMatters・buddyNote）だけ`EditableField`の編集→確定方式にする。

### 表示（畳んだ状態のとき）

評価済み（4動機のどれかが5から動いている、または価値観・人の項目に入力がある）なら、Checkpoint行の折りたたみ見出しに要約を出す。

```
▸ たて方の評価　動機+6・価値観2件・仲間あり
```

未評価なら何も出さない（空データにストレスを持たせない、という既存方針）。

### `/goals` 一覧・`/goal/[id]` への波及

今回は`/goal/[id]`のCheckpointEditor内で完結させ、`/goals`一覧には出さない。理由:

- 一覧はすでに「次の予定」「習慣」「中間目標の残り日数」で情報量が多い。評価は本人が内省するための道具であり、一覧で他人と比較したり急かされたりする性質のものではない
- 前回のCheckpoint実装と同じく、まず`/goal/[id]`で使ってみて、実際に評価すること自体が続くかを見てから一覧への露出を検討する

## 確認したいこと（実装前に竜一さんの判断がほしい点）
